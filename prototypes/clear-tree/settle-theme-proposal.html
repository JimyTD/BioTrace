一、美术预览页为什么会有文案 key？那都是啥

它是个开发页，用户走不到。路由是 /dev/settle-art（App.tsx:125）， 是美术走查开包舞台用的：能直接切阶段（?phase=）、切稀有度（?rarity=）、换样张（?photo=）、冻住中间态（?hold=1）。

那 8 条 key 就是这一页自己的说明文字：
settle.preview.title「开包美术预览」· settle.preview.lede「只看叠层效果，不走识别接口。点阶段切换封缄 / 揭示 / 展出。」· settle.preview.phases「开包阶段」（tablist 的无障碍名）· settle.preview.phaseSealed「封缄」· settle.preview.phaseReveal「揭示中」· settle.preview.phaseOpen「展出」· settle.preview.sampleName「示例标本」· settle.preview.ceremonySample「「潮间带」整册点亮（预览）」
为什么它会在这张表里：项目里走查页的惯例是 apps/web/public/themes/*.html 这类静态 HTML （皮肤主题.md §1 列的五个走查页全是静态页），只有它做成了 React 路由 + 消息表 key，所以它的开发说明混进了用户文案表。

我的判断：这 8 条不是用户文案——不该算进这次改造的工作量，也不该被皮肤 voice 覆盖（它们在固定区，机器上本来也覆盖不了）。 建议：本次不动，只在进度清单里标一句「开发页文案」。真要彻底对齐惯例，是把它挪成静态 HTML——那是另一件事，单独立案。

二、主题化机制：现状（我实读源码，不是文档结论）

· packages/messages/src/index.ts 里 VoiceId = "default"，覆盖表是内联对象 voices = { default: {} }，目前是空表。
· THEME_META 里两套皮肤（daylight / clear）都是 voice: "default"；applyTheme() 会调 setMessageVoice(meta.voice)，切皮肤即换词。
· 运行时闸：t() 里只有 themedKeys（＝ 可文案区 key 全集）才允许走 voice 覆盖，固定区一律走基础表。
· 服务端从不调 setMessageVoice，API 恒用基础文案。
一处文档已过期：皮肤主题.md §5 说覆盖表落在 packages/messages/src/voices/「一个皮肤一张」， 但那个目录现在不存在（灯箱退役时删了），表是内联在 index.ts 里的。

三、settle 里哪些该主题化

按《文案工程规范》§三 的判定三问筛：① 换了说法功能指代会模糊吗 ② 是事实/合规/数据表述吗 ③ 在安全或后果说明路径上吗

该主题化（15 条）—— 它们是「同一功能的说法」

settle.title · settle.lede · settle.open · settle.opening · settle.claim · settle.failed · settle.backAlbum · settle.volumeSlotLit · settle.volumeSlotLitMore · settle.volumeCompleted · settle.volumeCompletedMore · settle.volumeToCollection · settle.volumeCeremonyTitle · settle.volumeCeremonyCompleteTitle · settle.volumeContinue

理由：这一整套是仪式语感——「请过目」「收下」「点亮一格」「整册点亮」。同一功能的说法要成套一致， 而不同皮肤的开包动作本来就不一样（见下），所以这套说法天生该由皮肤给。

不能主题化（7 条）—— 三问命中，属固定区

settle.claiming「收录中…」—— 概念锚点：术语口径规定树上收录物统一叫「收录」，换说法会让跨页对不上
settle.rarity「稀有度」—— 概念锚点
settle.tierWeak「稀有度按已确认层级评定」—— 事实说明
settle.locationImprecise「无定位时按中国常见度评定」—— 事实说明（详情页也在用同一条）
settle.alertIntroduced「当地引入/关注种」—— 名录标签，概念锚点
settle.alertHint「依据该国公开名录判定」—— 事实说明
settle.notPending「这条没有结论可看。」—— 错误码译文

四、出示一版：两套皮肤各自的仪式说法

依据是它们真实在演什么（皮肤主题.md §2.4，我核对过组件）：
· 日光图版的开包是「拆封」——牛皮纸包、封蜡、壳被抬走。
· 清透（默认皮肤）的开包是「显出来」——照片带暖白边从一小叠里浮上来、由糊到清；它的四拍是拿起 → 显影 → 定色 → 落章。

所以同一句「请过目」，两套皮肤本来就该说不一样的话。下面这一版是我写的（未落生产文件）。
