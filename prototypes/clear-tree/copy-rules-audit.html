文案守则 · 逐条对

把现存所有文案守则摆出来，一条条过。你的判断优先——这是你要亲自把关的那一步。

先记住你的洞察：这些守则大多也是踩坑记录堆出来的，不是设计出来的。堆得越多，agent 越会「处处遵守」， 写出来越蹩脚——同一个需求，约束更少的模型反而更好。所以这轮的目标是「砍」，不是「加」。

A. 文案语感基准.md

原文我的判断
对用户一律「你」，禁用「您」留。清晰、有用，不干扰创作。
对生命一律「它」留。
不出现昵称化（「小家伙」「这位」）留。
黄金句式：现状句 + 行动句（trips.empty 为样板）存疑。把一种句式封「黄金」，会让所有空态长成一个模子。
界面句 ≤ 2 短句；单句静态字 ≤ 14，超了拆句或移固定区存疑。这是 lint 级硬线，逼人「为短而断句」，正是蹩脚句的来源之一。
仪式句允许 · 分隔，不按散文句法审留。
句号收尾，禁感叹号；toast 可无标点冲突。与下面 C1「尽量不用句号」直接打架，必须二选一。
疑问句只在真提问时用，不用反问做语气装饰留。
五大隐喻家族白名单；跨家族混搭禁止存疑。「白名单 + 禁止混搭」是很重的约束，容易把句子锁进五套说法里。
术语口径：统一「收录」；量词 格 / 本 / 项；项 ≠ 种留。术语统一是真有用。
新增文案硬约束①：先查能不能复用 common，不许直接新建留。
新增文案硬约束②：不做无意义兜底留（但「兜底」判断容易过头，见 C4）。
lint 只拦 5 项（感叹号 / 您 / 静态字 / 家族组 / 占位符）；文采节奏意境人评留。这条本身是对的——关键是别拿 lint 当文采标准。

C. 进度文档 · 文案纪律（本轮沿用）

原文我的判断
C1 尽量不用句号（多段独立信息除外）冲突。与 A7「句号收尾」打架；且「尽量」被我当成硬线，砍出过干瘪句。
C2 禁同义反复存疑。我用它砍过好句（「界面轻到几乎不见」）。「反复」的界在哪，谁定？
C3 亲切短句优于完整陈述存疑。它可能正是「大白话」的源头——亲切 ≠ 短 ≠ 好。
C4 说明性文案过「存在意义」三问，皆否 → 删存疑。三问是淘汰工具，我用它否定过「识万物」这种好修辞。用错对象就变凶器。
C5 事实正确 ≠ 需要告诉用户留。
C6 与界面已有元素重复的文字删留（但同样容易过头）。
C7 提案至少覆盖「删 / 合并 / 改措辞」三类留。这是审查方法，不是造句规则。
C8 判据用于淘汰，不用于生成留。这条最关键，但我自己反复违反。
