## 2. 设计

### 2.1 export-backbone.py：CROWN 表扩成八界

现状：表只有五界，三界被硬编码排除。

建议：加三行 `(3,"Bacteria","细菌界","root")`、`(2,"Archaea","古菌界","root")`、`(8,"Viruses","病毒界","root")`。界节点 zh 直接写进 backbone.json 的 zh 列（与五界同路）。文件头「根系不导」的理由段改写为历史记录，指回本方案。自检（id 唯一 / 无环 / 父不悬空）照旧，预计产物 ≈ 3803 节点（+1889），体积约 +75KB（gzip 约 +20KB），门/纲/目构成以脚本自检输出为准，不预设数。

### 2.2 treeModel.ts：删假枝

现状：三界界节点由 `ROOT_KINGDOMS` 手写、其下 `growFiller` 假枝；文件头注释整段解释「为什么根系是假的」。

建议：`ROOT_KINGDOMS`、`growFiller`、`buildSpeciesTree` 第 2 段（根系三界+假枝丛）整块删除。三界界节点改由骨架装载自然产生——**id 仍是 `0:Bacteria` / `0:Archaea` / `0:Viruses`（rank 0 + 拉丁名），与现状同 id**，这一点是 2.3 形态复刻的前提：形态种子 `strHash(id)` 不变，枝形逐枝可复刻。`attachEntry` 零改动（三界入库后细菌条目会命中真门枝，不再即时补建假位置）。文件头注释改为「三界真数据已入库，科属种照旧动态生长；假枝历史见 git 与本方案」。

### 2.3 TreeScene.ts：根区总览换「写死形态枝」（本方案核心）

现状：根区走 free 豁免——`vis=null`，filler 子树全部照长，茂密度由假枝基数决定；真数据若直接接管，171 门全部进总览缓冲，第一屏直接爆炸，违反拍板第 4 条。

建议：根区总览从「模型层假节点」换成「渲染层形态枝」，真门纲目**不进总览缓冲**，只在聚焦视图出现：

- 新例程 `rootBushOn`（命名施工时定）：界节点下按 `ROOT_B=[7,5,4]` 参数长形态枝。枝数公式、`h01` 抖动、长度/宽度公式**逐字照抄** `growFiller` 与真实子枝公式——`decoFillOn` 的既有教训：长度公式差一点就会在 `OV_LMIN` 收尾层错开。界节点 id 不变 → 种子不变 → 每界枝数序列与现状完全一致。
- `grow()` isRoot 分支重写：不递归真实子级，调 `rootBushOn`。根区形态参数（`spreadK 1.6`、`photo -0.06`、`t0 0.3`、竖直压扁 `-abs`、地面镜像 1219 行）全部保留不动。
- `growAll()` 预算同步：根区子树不 walk（界节点本身照计），形态枝预算与 `rootBushOn` 同一套公式。
- `growTrunk()` 根区摆位零改动。

**指纹口径**：末梢 14860 / 叶 198792 / 顶点 205680 一字不差（形态枝逐枝复刻保证）。真实枝 2124 → 约 1920、装饰枝 19220 → 约 19424：根区约 204 根假枝从「树节点」口径挪到「装饰枝」口径（总览不再画模型节点），总数 21344 不变——这正是铁律「真实枝与装饰枝此消彼长」的口径，验收按总数对齐。

**为什么这不是违背铁律而是贯彻铁律**：铁律 §1「第一屏形态写死、真实条数不参与」本就是树冠的既定待遇；本次只是把同一待遇推广到根区——总览看形态，点进去（fan 视图）看真数据，两屏之间有生长动画兜着。

### 2.4 聚焦视图：真扇出照既有兜底

现状：`pickKids` 全摆 + `FAN_CAP=20` 分页兜底，注释明言「翻页是常态，保穷尽性」；`fanFoliage` 每子级一根枝不递归。

建议：零机制改动。细菌界 171 门 → 9 页兜底；病毒 38 纲直接挂界（真实深度不齐，GBIF 如此）；代号门（UBA10199 类）`zh=null` 排后面、显示拉丁名——真数据的可读性代价，拍板时已知情。走查用 `?cap=40/60`。

### 2.5 SpeciesTree3D.tsx：sealed 卡片补真规模

现状：sealed 时不显示子级规模，注释理由「假枝丛不算细分。再说『还没有细分』像是在邀你往下走」。

建议：理由前半句随假枝消失。sealed 卡片显示真子级规模（如「38 纲」），按钮保持「不可收录 / 病毒不进入图鉴」不动——规模是真数据，不可收录是拍板第 3 条，两者不冲突。

### 2.6 messages：退役三个键

现状：`tree3d.kingdomBacteria/kingdomArchaea/kingdomViruses`（zh.ts 237-239 行）只被 `ROOT_KINGDOMS` 引用。

建议：删除，中文名随骨架 zh 列来。改完跑 `pnpm check:copy`。

### 2.7 三界中文名：复用既有补名管线（先例已找到，09-08 用户确认沿用）

现状：先例成型、可直接复用——backboneZh.ts 头注释 + scripts/fill-backbone-zh.py：

- 界/门（树冠五界）：上手填，全覆盖，只收通行中译。
- 纲/目：离线管线——Wikidata SPARQL 主源（对齐 学名+阶元+界，对不上留空），iNaturalist 补洞，zhconv 转简体，缓存续跑（scripts/_cache/backbone-zh-fill.json），合并进 backboneZh.ts「离线配表」块并标来源。
- 防线：wiki_zh_ok 后缀校验（纲须以 纲/类 结尾、目须以 目 结尾，科/属/种一律拒）；check-zh.py 揪死键。「GBIF 中文名覆盖率 0%」当年就是这条管线解决的，三界是同款问题。

建议：三界照抄同一套，脚本扩三处：

1. 管线扩到门级：RANK_WD / RANK_INAT / load_missing 覆盖 rank 1，wiki_zh_ok 加「门须以 门 结尾」，离线块 rank 标注加「门」。
2. SPARQL 的 kingdom 白名单加 Bacteria / Archaea / Viruses；iNat 对三界跳过（INAT_KINGDOM 不加——微生物中文名 iNat 本就稀薄，Wikidata 单源够用）。
3. check-zh.py 门级全覆盖对三界放宽为「报告缺额并列清单」，树冠五界维持全绿。代号门（UBA10199 类）自然 miss → `zh=null` 显示拉丁名，**不编造**。

纲 / 目照旧跑管线：有通行中译就配上，没有就 null 显示拉丁名。
