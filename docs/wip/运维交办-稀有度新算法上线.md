## 2. 必做：配 `TOKENHUB_API_KEY`（漏了会静默失效）

新算法**唯一**的必填新密钥。两条路任选，**推荐后台填**：

**路线 A（推荐）：管理后台 → 平台密钥 → 分组「稀有度」→ TokenHub 密钥。**
保存即生效，不必重启容器、不必碰服务器文件。落盘在数据卷里的 `admin-runtime-secrets.json`
（与库同级、已 gitignore），重建容器不丢。后台登录本身不依赖这个 Key，所以先上线再填没问题。

**路线 B：** 往服务器本地 `deploy/.env.production` 加一行，然后按 §7.1 重建 API。

```dotenv
TOKENHUB_API_KEY=<向主人索取>
```

两条都要注意：

- **不能填 Coding Plan 那种 `sk-sp-` 开头的 Key**，那类 Key 打不通 `chat/completions`。
- `.env.production` 已 gitignore、从未入库；**不要**尝试把它同步进 git（铁律）。
- 后台填的值会**覆盖** env 里的同名项。两边都配过时，改 env 不生效，要先在后台清空该槽位。

漏了的后果不是报错停机，而是更难发现的：模型链四档依次抛 `TOKENHUB_API_KEY is not set` 全部失败，
系统给每个物种发**临时 SR 且不写缓存**。SR 是合法档位，页面上看不出异常，但全站稀有度都是假的，
且因为不入缓存，每次开包都要把四档模型重试一遍。

其余 `RARITY_*` 变量（模型链顺序、采样次数、边界升采样、调用间隔）**都有默认值，不要配**。
清单见 [`SPEC.md`](../SPEC.md) §3.4，只在需要临时改模型优先级时才动。

## 3. 出网：TokenHub 走直连，**不**走出境代理

TokenHub 是国内服务。代码里为它单开了一个不带代理的 undici Agent，故意不继承全局 dispatcher——
沿用的话请求会被绕去境外代理再回来，慢且容易失败。所以：

- **不要**把 `tokenhub.tencentmaas.com` 加进代理链路，也不要因为它「是个 AI API」就往 `HTTPS_PROXY` 里塞。
- Gemini 那条出境代理链路照旧，`docker-compose.override.yml` 里的 `deploy/Dockerfile.cn` 与
  `extra_hosts: host.docker.internal:host-gateway` 仍必须保留。

容器内直连是否通（任何 HTTP 状态码都算通，只要不是超时或 DNS 失败）：

```bash
cd /opt/biotrace && sudo docker compose exec -T api node -e "fetch('https://tokenhub.tencentmaas.com/v1/models',{headers:{Authorization:'Bearer '+process.env.TOKENHUB_API_KEY}}).then(r=>console.log('HTTP',r.status)).catch(e=>console.log('ERR',e.message))"
```

## 4. 首次启动会自动改库并删旧缓存——**先备份**

API 启动时自动迁移，无需手动 SQL，但这次含一条**不可逆删除**：

- `rarity_cache` 加 7 列（得分、12 题答案、加减明细、生效模型、采样次数、名录级别、理由）
- `DELETE FROM rarity_cache WHERE cache_key NOT LIKE 'scale%|%'`——**旧 `enc4` 缓存行开机即清空**

所以按 §8 先打一包再重建：

```bash
sudo tar czf /root/biotrace-data-$(date +%F).tgz -C /opt/biotrace data
```

清掉的只是缓存（可重算），观察和图鉴数据不动。但如果这次上线出了问题要回滚到旧版 API，
旧缓存已经没了，旧算法会重新问模型——**回滚前先确认备份在手**。

## 5. 老数据怎么办：**按主人的决定，不管它**（可选工具）

第 4 节只清了缓存，已结算观察和图鉴里存着的档位还是旧算法算的，不会自动变。

**主人的原话是「如果有残留数据 就不管他，或者全面清库都行」，所以这一步不是必做项。**
新观察一律走新算法；老观察留着旧档位是可接受的。**不要**为了「口径统一」自行去跑重算。

需要时才用（比如主人明确要求把老档位刷新）：后台 → 稀有度缓存页 → 「批量重算未评物种」。
默认一次 10 个（上限 50），只处理还没有量表缓存的物种，幂等，按钮会回报剩余数，可反复点。
会顺带把该物种已结算/待开包的观察和图鉴改成新档。慢是正常的：每个物种至少 3 次模型调用，
免费档并发 1、约 1 req/s。中断没有副作用。

2. 第 3 节那条容器内直连命令回 HTTP 状态码，不是 ERR。

   - **模型链诊断**：四档都没有冷却、没有最后错误（`GET /api/admin/rarity-models`，需管理员登录，

   - 平台密钥页「稀有度」组里 TokenHub 密钥显示为已配置。
