# 留影档：拒绝收集政策的重构（设计方案 · 定稿）

> 状态：**已拍板，待施工**（2026-09-08）

## 1. 为什么要改

用户拍风景照、街头随手拍、茶杯、滑滑梯，本来就没想"收集"。系统却回红字：

```
东西是真的，但专家说这个不算收集品。   ← error.identifyNotCollectible
图是好图，专家说图鉴不收。             ← error.identifyNotCollectibleHint
```

用户不爽的**不是没给稀有度**，是被系统用报错语气否定了拍摄行为。
更糟的是落库清空身份字段，一张认真拍的照片只剩一句否定。

**核心认知（用户拍板）**：照片永远是照片，图鉴身份是附加层。
**红字纪律（用户原话）**：现在那套报错一样的语气+大红字 除非真报错不然不要用了。

## 2. 判定口诀

改任何一档、写任何一句文案前先问：

> **是系统坏了，还是只是没进册子？**

- 系统坏了（服务挂、额度尽、Key 没配、超时） → 才配红字
- 只是没进册子 → 中性灰 + 陈述句

项目内先例：包装边界的判定口诀是"隐喻只许换名字，不许造前史"。同一用法——一句话、事前自检，不是用户文案。

## 3. 三档模型（取代收/不收二元）

| 档位 | 触发 | 相册 | 标题来源 | 稀有度 | 图鉴/套册/树 |
|------|------|------|----------|--------|--------------|
| **相遇** | 真实现场生物 | 保留 | `commonName` | 有 | 进 |
| **未相遇**（软档） | 真生物非野外：影像/标本，有身份有界 | 保留 | `commonName` | 无 | 不进 |
| **留影**（新增） | 其余全部：无生物/仅背景/unclear/人/器物/没界 | 保留 | **agent 输出短标题** | 无 | 不进 |

**留影档覆盖**（原来全部走红字硬拦）：`no_organism`、`unclear`、`human`、
`artifact_or_toy`（茶杯、玩具、雕像）、`no_kingdom`。
**不并入留影**：`too_coarse`（只认到大类）保留独立码，仅把视觉从红改中性灰。

## 5. 展示层统一 `subjectTitle`（关键设计）

后端 `IdentifyResult` 新增**可选**字段 `subject_title_zh`（snake_case 对齐现有风格）。
三档展示同一个槽位，来源不同：

```
title = subjectTitle ?? commonName ?? scientificName ?? t("detail.unnamed")
```

- 相遇 / 未相遇：没有 `subjectTitle`，回落到 `commonName`（物种中文名）
- 留影：识图 agent 输出短标题，一行内、不限制题材（《茶杯》《桂林山水》《滑滑梯》）

现有硬拦分支 `title = notCollectible ? t("detail.notCollectibleTitle") : ...` 的
死文案分支**一并删掉**，留影档也走回落链。

## 6. 区分度靠什么承载（回应"是不是过于宽容"）

**担忧**：统一展示 `subjectTitle` 后，生物和非生物在标题上没区别，会不会把图鉴稀释成相册。

**判断：不会。区分度不挂在标题上，挂在这六处**：

1. **稀有度章** — 留影档没有（只有相遇档有）
2. **留影印章** — 占稀有度章的位置，纸灰、无辉光（照 `SoftEncounterSeal` 的路子自绘）
3. **学名** — 留影档 `scientificName` 为空，不显示
4. **分类阶元** — 留影档 taxonomy 全 null，详情页 `showTaxonomy` 分支自动跳过
5. **进不进图鉴** — 留影档 `taxonKey`/`rarity` 为 null，图鉴/套册/物种树天然不收
6. **相册徽章** — 中性灰"留影"，区别于"相遇"

**所以"宽容"的是相册层，图鉴层一点没松。** 相册本来就该宽容（照片永远是照片），
图鉴才是收集品。留影档只进相册张数，**绝不进任何"种数/收录数"统计，不进图鉴页**。

### 6.1 地图规则（用户 2026-09-08 拍板）

**只有「相遇」档进地图。未相遇（软档）与留影档都不进地图。**

- 现状：地图原未区分档位，凡有坐标即打点；软档/留影混入后地图从「生物分布图」
  变成「我去过的地方」——《茶杯》《滑滑梯》打上去，稀释物种语义
- 建议：地图数据源只取 `taxonKey` 非空 且 非软档/非留影 的记录；
  软档与留影档坐标照存（详情页仍可显示"拍于哪里"），但**不产生地图点**
- 连带：留影档是否给地理标签不再纠结——坐标照判照存，只是不打点

## 7. 现状实锤（改前基线）

### 7.1 资格闸（`apps/api/src/identify/eligibility.ts`，142 行）

非此即彼：`ok:true`（仅 `living_organism`+`collectible`）/ `ok:true+soft`（仅
`depiction_or_media`/`specimen` 有身份有界）/ 其余**全硬拦**（4 个码）。

**改造后**：三个分支 → 相遇 / 未相遇 / 留影。**不再有 ok:false 硬拦**，
四个码全部归留影。硬拦（红字）只剩真故障，而真故障不在本闸（在 `identify.ts`）：
`identify_unavailable` / `identifyQuota` / `identifyDailyLimit` / `identifyUserKeyIncomplete`。

### 7.2 留影档为何天然不进图鉴

软档已验证：`status=settled` + 错误码结构，**不结算** → `taxonKey`/`rarity` 为 null
→ 图鉴、套册、物种树天然不收。留影档**照抄结构复用**，下游一处不用改。

### 7.3 红字渲染点（两处，都要改）

| 文件 | 位置 | 现状 |
|------|------|------|
| `apps/web/src/pages/TripAlbumPage.tsx` | `statusBadge()` L59/L63 | `isNotCollectibleError`/coarse/failed 全 `badge danger` |
| `apps/web/src/pages/ObservationDetailPage.tsx` | L365/L375 + L307 标题 | 同上 + `<p className="error">` + 死文案标题 |

中性灰基建**已存在**：`badge.soft`（`SoftEncounterSeal.css` 注释明确
"区别于 danger 红（硬拦）与 warn 黄（进行中）"），只是没给硬拦用。

### 7.4 文案（全在固定区 `zh.ts`）

| key | 现状 | 处理 |
|-----|------|------|
| `error.identifyNotCollectible` | 东西是真的，但**专家说**这个不算收集品。 | 删/换陈述句 |
| `error.identifyNotCollectibleHint` | 图是好图，**专家说**图鉴不收。 | 删/换陈述句 |
| `error.identifyTooCoarse` | **专家只敢**认到大类。 | 保留码，视觉改中性灰 |
| `status.notCollectible` | 徽章 | 改"留影" |
| — | — | 新增 `status.keepsake`、`error.identifyKeepsake*` |

**红字保留**给 4 个真故障码。其余一律中性灰。
上述 key 全在**固定区**，voice 不可覆盖，改完**必须**跑 `pnpm check:copy`。
