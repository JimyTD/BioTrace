## 1. 这次改了什么

识图结果增加三层信息：

| 区块 | 回答的问题 | 实现 |
|------|------------|------|
| 简介 | 这是什么，最鲜明的特征是什么 | 将原 `blurb` 从泛科普短文收成一句话物种名片 |
| 识别说明 | 这张照片为何判成它，哪里不确定 | 沿用原 `notes` 字段，只改用户可见标题；Prompt 改为依据 + 不确定 |

## 2. 字段与展示

### 2.1 简介

- 一句话，20～60 个汉字。
- 只写最鲜明、最有辨识度的特征。
- 不重复分类链，不写用途、食用性、保护级别、稀有度、文化含义。
- 不写生境、食性和物候，这些归生态习性。
- 不写照片证据和不确定性，这些归识别说明。

### 2.2 识别说明

- 字段仍是 `notes`，不改数据库与 API 形状。
- 先说照片中实际可见、支持当前结论的特征。
- 再说不确定性、混淆点或阶元局限。
- 没有可见依据时只写不确定性；没有额外不确定性时只写依据。
- 两句合计不超过 60 字。

软档与留影继续把模型原始不合格理由保存在 `identifyReason`；
识别说明与档位理由都留底，不再互相覆盖。

### 2.3 生态习性

总标题统一叫“生态习性”，不按八界分别造标题。当前骨架八界为：

`Animalia` / `Chromista` / `Fungi` / `Plantae` / `Protozoa` / `Bacteria` / `Archaea` / `Viruses`

内部固定三项：

| 用户标题 | 内容 |
|----------|------|
| 生境 | 通常在哪里出现，依赖什么环境或宿主 |
| 习性 | 如何取食、活动、生长或与其他生命发生关系 |
| 物候 | 出现、开花、结果、繁殖或流行的季节规律 |

显示规则：

- 最多三条，按“生境 → 习性 → 物候”排序。
- 每条约 10～30 个汉字，一个短句。
- 某项没有可靠内容就省略。
- 三项全空时整块“生态习性”不渲染。
- 结算揭示页最多展示前两条，详情页展示全部可用项。

## 3. 排版

详情页：

`名称与学名 → 简介 → 生态习性 → 分类 → 记录`

“识别说明”留在现有“记录”区，只把标题从“识别备注”改成“识别说明”。
本次没有把它从记录里移出，避免扩大改动面。

结算页：

- 揭示后继续显示名称、学名、稀有度、标签。
- 简介显示一句。
- 有可靠生态习性时，最多显示前两条。

## 4. 主题约束

- 不改默认 `clear` 的既有观感，不加新的视觉概念。
- 复用现有 `detail-block` / `section-title` 结构和语义 token。
- 新增样式只用现有 token：没有为本次新增主题变量。
- 不新增 `themes/slots.ts` 槽位：这是共享内容结构，不是换物件或换演法。
- `clear` 与 `daylight` 共用同一结构，不分别做版式。

## 5. 数据

数据库新增三列：

- `habitat_zh`
- `habit_zh`
- `phenology_zh`

它们与 `blurb`、`notes` 一样落在观察行上，旧观察缺省为 `null`，
不批量回刷。重识别时会先清空，再写新一次识图结果。

## 6. Prompt 契约

- `blurb_zh`：一句话物种名片。
- `habitat_zh`：通常生境。
- `habit_zh`：取食、活动、生长或种间关系。
- `phenology_zh`：季节规律。
- `notes`：识别说明，先说照片依据，再说不确定。

生态习性与简介都按已识别分类单元书写，不把单张照片当天气、
季节或生活史证据；没有把握的项必须留空。

## 7. 验收

- 详情页显示一句话简介、可用生态习性、识别说明。
- 结算页显示简介与最多两条生态习性。
- 生态习性三项全空时整块不渲染。
- 旧观察没有新字段时不崩、不显示空壳。
- 重识别后旧习性被清空，再写新结果。
- `clear` 与 `daylight` 共用同一结构，无横向溢出。
- 后端类型检查、前端构建、`pnpm check:copy` 通过。

## 8. 暂不纳入

- 用户手动编辑简介或生态习性。
- 以生态习性反推或修正分类。
- 自动回刷更新前全部历史观察。
- 把保护级别、引入状态、稀有度并入生态习性。
- 为八界分别创造八套视觉组件或主题槽位。
- 独立的识别依据 / 不确定性字段。
- 物种档案缓存表。
