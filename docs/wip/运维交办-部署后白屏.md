# 运维交办：部署后安卓端白屏（只显示背景）

> 2026-08-18。前端侧修复已入库，**服务器侧待执行**。权责：本文「待执行」两节归运维 agent；「已在仓库完成」一节不必再动。

## 1. 现象

安卓侧载包打开后一直只显示背景，页面不挂载，无任何报错提示。持续约 18 分钟（15:34 → 15:52 多次打开均如此），清掉 App 缓存后立即恢复。**期间服务器未做任何改动**，仅清客户端缓存即好——故障不在线上代码。

## 2. 证据（nginx access log，客户端 IP 59.37.125.76，Android WebView）

同一个 URL 在部署前后返回的东西不是一回事：

```text
15:01:28  GET /assets/index-BKtpjPRN.js  200  1829273   ← 真的 JS
15:31:31  部署：rsync -a --delete 同步新产物，旧哈希文件被删除
15:34:52  GET /assets/index-BKtpjPRN.js  200      503   ← 869 字节 index.html 压缩后
15:35:18  GET /assets/index-BKtpjPRN.js  304        0
15:36:43  GET /assets/index-BKtpjPRN.js  304        0
15:43:46  GET /assets/index-BKtpjPRN.js  304        0
15:52:46  GET /assets/index-BKtpjPRN.js  304        0
15:53:27  GET /  200 + 新 CSS + 新 JS               ← 清缓存，恢复正常
```

注意 15:34 之后这些时间点，客户端**只请求了这一个文件**：没有 HTML 文档请求、没有 CSS、没有任何 `/api/*` 调用。

## 3. 根因

三件事叠加，缺一不可：

1. 前端产物文件名带内容哈希，部署用 `rsync -a --delete`，**旧哈希文件当场删除**；
2. `index.html` 响应**没有 `Cache-Control`**，客户端只能按启发式推算新鲜度（约「距上次修改时长」的 10%）。今天 15:31 是十五小时来第一次部署，而手机 15:01 刚加载过，算出来的新鲜期一个多小时，于是它一直不回源，攥着旧 index 去请求已被删掉的 JS；
3. nginx 的 SPA 兜底 `try_files $uri $uri/ /index.html` **对 `/assets/` 也生效**，把这个请求兜成了 `200 + text/html`。浏览器拿 HTML 当 ES module 解析直接失败，React 永远挂不上——只剩背景，且不是 404，排查时毫无线索。

该缺陷一直存在，只是需要「手机缓存正热 + 紧接着一次部署」才会触发，所以此前未暴露。验证仍在复现：

```bash
curl -s -D - -o /dev/null http://106.53.188.20/assets/does-not-exist.js   # 现在返回 200 + text/html
```

## 5. 待执行 A：修 nginx 缓存规则（本次白屏的根治项）

改 `/etc/nginx/sites-available/biotrace`，在现有 `location /` **之前**插入两条（完整模板见 `docs/OPS.md` §4.6）：

```nginx
# 带哈希的产物长缓存，但缺失时必须 404，不能被 SPA 兜底成 HTML
location /assets/ {
    try_files $uri =404;
    add_header Cache-Control "public, max-age=31536000, immutable";
}
# index.html 不缓存：过期副本会指向已被删除的产物
location = /index.html { add_header Cache-Control "no-store"; }
```

然后 `sudo nginx -t && sudo systemctl reload nginx`。

> 该文件不受 git 跟踪，属服务器运行态，改它不违反「服务器上不改被 git 跟踪的文件」这条铁律。
