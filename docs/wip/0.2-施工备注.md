## 1. 当前段：识图护栏

### 1.1 来源（原则，非实现清单）

[`planning/05-技术方案.md`](../planning/05-技术方案.md) A.5：

- 平台默认 Key 在后端；默认 Gemini，备选智谱  
- 「我的」可存用户自备 Provider + Key；此后该用户识图走自备 Key  
- 前端永不打包平台 Key；用户 Key 入库、不完整回显  
- 每账号每日**默认**识图次数上限（N 未定）；超限提示自备 Key 或次日  
- 可加 IP / 全局限流（非本段必做）

现状（代码粗看）：有供应商侧 `identify_quota` / Gemini `daily_exhausted` 回退 GLM；**没有**按账号的日额度计数，也没有用户自备 Key 存储与路由。`SPEC` §5「我的」仍写自备 Key / 日额度后置。

### 1.2 本段目标（草案，待讨论锁死）

先做能挡住「注册即可刷爆平台 Key」的最小闭环：

1. **账号日额度**：仅消耗**平台默认 Key**的识图计入；超限拒绝新排队/新识图，稳定 error code + messages 文案。  
2. **自备 Key**：在「我的」写入/清除；有自备则该用户识图走自备，**不占**平台日额度（失败策略另定）。  
3. **不在本段**：IP/全局限流、未登录逛壳耗额度、多 Provider 花活、账单级用量看板。

### 1.3 已拍板 / 待讨论

| # | 题 | 状态 | 结论 |
|---|-----|------|------|
| Q1 | 默认日额度 N | ✅ | **100 / UTC 日 / 账号**；env `IDENTIFY_DAILY_LIMIT` 可改；`0` = 关闭账号日限额 |
| Q2 | 什么算一次 | ✅ | 每次实际调用**平台**识图扣 1（含重识别）；`failed` / 不可收集也扣；排队未跑不扣；自备 Key 全程不扣平台额度 |
| Q3 | 日界 | ✅ | **UTC 日** |
| Q4 | 超限体验 | ✅ | **松**：超限仍可上传进相册，**不跑识图**（失败态 + 文案引导填自备 Key / 等 UTC 次日）；重识别同理拦截。不把注定失败的活推进队列 |
| Q5 | 自备接哪些家 | ✅ | **方案 A**：仅 OpenAI 兼容口（Base URL + API Key + Model）；不设 Gemini/智谱用户预设 |
| Q6 | 自备失败 / 开关 | ✅ | **显式开关**「使用我的 Key」；开着则自备失败**硬失败**、不回落平台；关上 → 平台默认（计日额度）；Key 可留着只关开关 |
| Q7 | Key 存储与回显 | ✅ | 服务端加密；API 只回已配置标记 + 后四位等 hint；可清除 |

#### 1.3.1 自备 Key（已定摘要）

- **A**：用户自备只走 **OpenAI 兼容** 一条适配（Base URL + Key + Model 均必填）。  
- 平台默认仍是后端 Gemini → 智谱回退（我们自用免费效果好）；与用户自备通道分离。  
- 开关打开 → 只用用户兼容口，不掺平台 Key / 回退链。  
- 不做：厂商预设下拉、模型列表探测。  
- 「我的」：开关 + 三字段表单 + 今日平台 `已用/100`（仅走平台时计数）。  

**本段仍不做：** IP/全局限流、用量看板、多 Key 负载均衡。

#### 1.3.2 本段已全部拍板

| 项 | 结论 |
|----|------|
| 日额度 | 100 / UTC 日 / 账号；`IDENTIFY_DAILY_LIMIT`；`0`=关 |
| 扣次 | 平台识图实际调用才扣（含重识别、失败/不可收集）；自备不扣 |
| 超限 | 可上传不识图；引导自备 Key 或次日 |
| 自备 | OpenAI 兼容三件套 + 显式开关；开=硬失败不回落；关=平台 |
| 存储 | 服务端加密；回显 hint 后四位 |
