## 块 A：系统形态（已结案）

### A.1 总览

```text
[Web App] ──┐
            ├── HTTPS/JSON ──► [Node/TS 薄后端] ──► Gemini（默认）/ 智谱（备选）
[Android 壳]┘                      │
                                   ├── 元数据库（厂商待定）
                                   └── 展示图等文件存储（厂商待定）
客户端 ──直连──► 天地图瓦片 + MapLibre（失败：备用浏览器端 key → 内置简图）
国内腾讯云 API ──经新加坡代理──► 国外 API（Gemini 等）
```

### A.2 客户端

| 项 | 结论 |
|----|------|
| 第一版目标 | **Web + Android**；iOS 后做，共用同一套后端 API |
| 形态 | **A：Web 为主 + Android 薄壳**（TWA/WebView 一类） |
| 为何 A | 第一版问题面更小（地图走已验证的 MapLibre GL JS）；不按个人技术栈选型 |
| 升级路径 | 若壳在选图/EXIF/地图上撞墙，再评估 RN/Flutter（B） |
| 地图 | 引擎 **MapLibre**；底图 **天地图**（浏览器端 key）；回落 **备用 key → 内置 Natural Earth 1:50m 简图（China POV）**；后端不代理瓦片。已移除 OpenFreeMap（见 `04f` §12） |
| 防灰屏 | 由回落链保障（见 `04f` §12）；勿再依赖 OSM 公共瓦片 |

### A.3 后端

| 项 | 结论 |
|----|------|
| 角色 | 薄 API：登录、识图代理、观察/旅途 CRUD、展示图处理与存储接入 |
| 语言 | **TypeScript (Node)** |
| 将来本地 CV | 可另起 **Python** 工人，经 HTTP/队列与主 API 约定接口，不必重写主站 |
| 部署早期 | 用户 **腾讯云国内机**；具体 DB/对象存储产品 **待定**（看腾讯云方案再选） |

### A.4 账号与登录

| 项 | 结论 |
|----|------|
| 要登录 | **轻量登录**；默认识图额度、自备 Key、观察/旅途均挂账号 |
| 方式 | **邮箱 + 密码**；长会话（Cookie + 滑动续期）；日常不发信 |
| 邮件 | **仅找回密码**（Resend 免费档；App 内填重置码优先）；**不强制注册验邮**（假邮箱可注册，收不到信则无法找回） |
| 未登录 | 不消耗平台默认识图；逛壳/演示见 D.4（后置） |

### A.5 识图 Key

| 项 | 结论 |
|----|------|
| 平台默认 | 后端持有 Key；**默认 Provider = Gemini**；**备选 = 智谱** |
| 用户覆盖 | 设置里可存自己的 Provider + Key；此后该用户识图走自备 Key |
| 前端 | **永不打包平台默认 Key**；用户 Key HTTPS 入库，不完整回显 |
| 防冲爆 | **每账号每日默认识图次数上限**（N 以后定）；超限提示自备 Key 或次日；可加 IP/全局限流 |
| 出网 | 国内机经用户已有 **新加坡代理** 访问 Gemini 等；开发时补代理配置/小组件 |

### A.6 照片与存储

| 项 | 结论 |
|----|------|
| 库 | 只存**元数据** + 文件路径（或等价引用）；大图不进 SQL |
| 保留档位 | **仅识别** / **展示图** / **保留原图**（用户可选） |
| 默认 | **展示图**（识图可用更高清临时图；长期存压缩展示图） |
| 尺寸 | 具体像素/边长**以后定** |
| 厂商 | 对象存储/库 **腾讯云部署时再选** |
| 社交看他人图 | 非本阶段（P2）；账号与可见性设计勿堵死日后分享/看他人 |

### A.7 核心数据对象（草案，块 B 可细化字段）

| 对象 | 含义 |
|------|------|
| User | 邮箱 + 密码；可选 displayName；可选自备识图凭证；日额度计数；日后可见性/关注等扩展位 |
| Trip | 用户自建旅途分组 |
| Observation | 一次观察：时空、分类结果、展示图引用、所属旅途等（**无**用户手改分类字段；纠正走重识别） |

## 块 B：主路径交互（已实现 · 原则如下）

### B.1 主路径（已改主意，2026-08-05）

**动机：** 若选图后立刻把鉴定/时空等信息摊开编辑，没有「开包」感，差异化不如直接用 iNat。抽卡结算要当揭示高潮。

**流程（已定骨架）：**

1. **先进入某个自建旅途** → 相册选图并上传（可选填描述；选完即提交分析，中间不进 iNat 式确认编辑页）。  
2. 条目出现在**该旅途相册**里，状态为 **「分析中」**（可离开去做别的）。  
3. **分析完毕** → **弹框或整页**进入 **抽卡结算**。  
4. **结算页**再带上类 iNat 信息（鉴定、备注入口、日期时间、位置等）；揭示与收集感在前，明细在结算里/后。归属旅途在上传时已定。

此前「选图 → iNat 确认页 → 再识别/保存」方案 **作废**；iNat 截图改为 **结算页信息架构参考**，不是选图后的第一屏。

### B.2 「分析中」落点（已定）

- **B：先选旅途，条目进该旅途相册**（用户认为更酷；不做统一收件箱作主路径）。

### B.3 与参考界面的映射（结算阶段，草案）

| iNat 元素 | 出现时机（BioTrace） |
|-----------|----------------------|
| 媒体 | 旅途相册缩略图（分析中可见图）；结算页再展示 |
| 鉴定（俗名/学名等） | **结算揭示时**才完整亮出（可配合稀有度） |
| 备注 / 日期时间 / 位置 | 结算页可带；默认可来自 EXIF |
| 位置可见度 | **不做** |
| 添加至项目 | 上传前已选 **Trip**；结算不再重选（可后置「移旅途」） |
| 底栏大勾 | 语义改为结算确认/收下（细节待定） |

### B.4 分析完毕如何进结算（已定）

- **3：推送/轻提示 + 旅途相册可补开**  
  - 分析完可主动提示（弹层/整页，具体形态块 D 再抠）；  
  - 若当时忽略或错过，旅途相册条目变为「可开包/待结算」，点进同样进抽卡结算。

### B.5 识别「够格」界定（原则已定 · 落地见 `SPEC.md`）

**共识（仍成立）：**

- **不能**用「是否到种」当理想线——种级高置信现实中很少。  
- **不能**把「界/门」级当成功（Seek「动物界 / Arthropods」= **未理想**）。  
- 默认直觉：**多数情况属 = 舒服成功线**；种 = 加成。

**当前落地（固定阶元门槛，见 [`SPEC.md`](../SPEC.md)）：**

- `finest_reliable_rank` → `settle_tier`：种/亚种/属 → `full`；科（及近缘科级）→ `weak`；更粗 → `none`。  
- 不可收集对象（人/玩具/印刷等）在识图闸门拦截，不开包。

**后置方向（未做）：** 按分类树下属属/种数量自动判「小科/大科」动态够格；全量名录灌库。原则仍可参考下文历史方向，**勿当作已实现规则**。

**抽卡侧三档（已定）：**

> 下表左列是**规格档位名**（对应 `settle_tier` 的 `full/weak/none`），不是界面文案。
> 界面文案统一在 `packages/messages/src/zh.ts`，2026-08-10 已改口径：
> 相册状态 badge 为 `专家鉴定中 / 鉴定完成 / 已收录 / 未能认定 / 结论偏粗 / 不可收集`；
> 结算页为 `鉴定证书 / 请过目 / 请稍候… / 收下 / 收录中…`。
> **「开包」「抽卡」「揭开」已从界面清除**（用户不理解这些内部概念），但作为**内部概念名**在文档与key 名里保留。

| 档 | 含义（交互） |
|----|----------------|
| **结算**（full） | 够格：正式抽卡揭示 |
| **弱结算**（weak） | 有方向但不够理想：可开弱卡，明示阶元与局限；**稀有度不降档** |
| **未理想识别**（none） | 过粗或不可用：不开正式抽卡；相册失败/待补态，可重试<br>（界面此态文案为「结论偏粗」） |

### B.5.1 动态规则（后置，非当前主路径）

- 曾定方向：按下属属/种数量自动算小科/大科（及总科等是否够格）。  
- **现状未接主路径**；阈值与数据源见 `SPEC.md` §8 后置。

### B.6 上传描述与地理信息（已定）

- 上传时可附带**描述**（可选），一并进分析 Prompt。  
- Prompt 硬约束：**以图片视觉证据为主**；描述仅辅助。禁止被文案带跑（例：图是野猪、文写「这就是一条蛇」→ 仍应按图判）。  
- **无 EXIF/GPS**：  
  - 描述里若写了地点 → 可作**参考先验**注入 Prompt，但置信/权重低于真实坐标，不作硬事实；  
  - 图无地址且描述也无地点 → **就没有地点**，照常分析与结算；**不弹提醒、不卡住上传**。  
- 不做「分析前强制地图补标」；缺位置不阻塞主路径。  
- **事后地图补标**（无坐标时准星选点、重算国别/引入/稀有度、不重跑识图）：已落地，真源 [`SPEC.md`](../SPEC.md) §1.3。

### B.7 结算「收下」后（已定，低优先级可改）

- **1：回到该旅途相册**（刚收下的条目已揭开）。日后若要「去图鉴」入口可加，不挡主路径。

### B.8 待定 / 后置

- 三档各自：提示形态、相册态、稀有度怎么打折（并块 C）  
- 动态规则阈值与个案核实（专项）  
- 结算页内类 iNat 字段的编辑深度（块 D）

## 块 C：抽卡与引入警示（已实现 · 原则如下）

承接需求 F1/F2、H4/H5。与块 B 衔接：抽卡在**结算揭示**；警示在结算打出（详情可回看）。  
实现与验收以 [`SPEC.md`](../SPEC.md) §3 为准；旅行套册（成就）见 §7 / [`features/旅行套册.md`](../features/旅行套册.md)。

### C.0 承接前提（已落地）

- 警示：按**观察地点 + 公开/权威名录**；对外「当地引入/关注种」。  
- 抽卡：`N–XR` 七档收集感；无随机、可解释；**不叠**旅途/个人首次。  
- 结算三档：full / weak / none；**弱结算不降**稀有度。

### C.1 讨论顺序（已定）

- 先 **抽卡 / 稀有度**，再入侵警示。

### C.2 抽卡稀有度（原则已定 · 实现见 `SPEC.md` §3）

保留不变的产品原则：

- **完全不做随机**：同观察条件 → 档位稳定、可解释。  
- **相对「当地」= 国家级**；弱结算**不降**稀有度；**不叠**旅途/个人首次。  
- 语义是旅行「好不好遇见 / 有无收获感」，不是公民科学上传量。

**实现换维（2026-08-07，以 `SPEC.md` §3 为准）：**

- 主路径**不再**是 GBIF count 预计算表，也**不再**是轴分加权。  
- 流程：GLM 输出 `encounter_class`（分桶）→ 本地否决/映射 → `N–XR` 七档。  
- 禁止物种硬编码名单；判定键写在共享 rubric（生产=标定）。  
- 细节、流程图、环境变量、标定结果 → [`SPEC.md` §3](../SPEC.md)。

### C.2.1 档位命名（已定 · 已扩展）

- 对外：`N / R / SR / SSR / UR / LR / XR`（文案在 `packages/messages`）。  
- `XR` = 近乎不可能兜底（功能灭绝等），不是报警 UI。

### C.2.2 无国家 / 弱结算（已定）

- 无国家：**仍可开包打 encounter 档**；稀有度 **按 CN 评**（Prompt / 缓存键同一回落）；结算文案「无定位时按中国常见度评定」。不强制地图补标；不改全球口径。实现见 [`SPEC.md` §3.6](../SPEC.md)。  
- 弱结算不降稀有度：按 `finest_reliable_rank` 对应类群，与 full/weak 脱钩。

### C.2.3 不与「首次」挂钩（已定）

- **不做**旅途首次 / 个人图鉴首次抬档。

### C.3 抽卡小结

主规则：无随机、国家尺度、七档 encounter 分桶+否决、弱结算不降档、不叠首次、无物种黑白名单主路径。  
实现规格以 `SPEC.md` §3 为准；结算动效见块 D。

### C.4 引入/关注种警示（已定 · 实现见 `SPEC.md` §3.5）

#### C.4.1 露出时机（已定）

- **1：结算揭示时就打**（与开卡同一高潮，不藏到事后详情）。

#### C.4.2 文案（已定）

- 先 **B：偏中性**——对外用 **「当地引入/关注种」**（或同类说法），不先上「入侵种」硬词。  
- 对齐需求 H4；日后若名录带更强标签再考虑加档（不挡 MVP）。

#### C.4.3 匹配粒度（已定）

- **1：国家级**——按观察点所在国 × taxon 查「是否当地引入/关注」；与稀有度空间粒度一致。  
- 名录：GRIIS 国家 checklist（经 GBIF）作主索引 + 手写 seed 补丁；实现见 [`SPEC.md` §3.5](../SPEC.md)。  
- 不做省/岛级匹配（后置）。

#### C.4.4 无国家 / 鉴定阶元（已定 · 与实现一致）

- **无国家 → 不警示**：没有「当地」就无法匹配名录，**不编、不猜、不弱提示全球引入**。  
- **仅种 / 亚种可靠鉴定才警示**：名录为种级二项名精确匹配；属级（虽属 full 结算）与弱结算（科级）**一律不警示**。  
- （旧表述「弱结算能对上名录仍可警示」已废止——科级对不上种名录，且与种级闸门冲突。）

### C.5 块 C 小结

| 主题 | 要点 |
|------|------|
| 抽卡 | 无随机；encounter 分桶+否决 → `N–XR`；无国家仍可打档且**按 CN 评**；弱结算不降稀有度；不叠首次；无物种黑白名单 |
| 警示 | 结算揭示打出；文案「当地引入/关注种」；国家级名录；无国家不警示；仅种/亚种精确命中 |

后置：省/岛级匹配、结算动效细化（块 D）；稀有度 XR/中档校准见 `SPEC.md` §3.6。  
名录实现：GRIIS Country Compendium 全球 + GBIF China 覆盖 CN（见 `SPEC.md` §3.5）。

## 块 D：UI 信息架构（初步够用，已搁置）

> **性质说明（用户 2026-08-05）：** 本块所记均为**很初步的体验草案**，方便先按这个跑通手感；**不属于**此前 A–C / 需求里的核心硬约束，**后面肯定要改**。实现与评审时勿把 D 当不可动规格。  
> 定导航与关键屏职责，不定视觉高保真。  
> 已承接：主路径在**旅途相册**；结算/开卡/警示是高潮叠层；地图散点；个人图鉴回看。

### D.0 关键屏候选（草案，待收束）

| 屏 | 职责 |
|----|------|
| 旅途列表 | 自建旅途入口 |
| 旅途相册 | 分析中 / 待开包 / 已揭开；上传入口 |
| 抽卡结算 | 揭示 + N–XR + 引入警示 + 类 iNat 信息 |
| 世界/个人地图 | 观察散点浏览 |
| 图鉴/收集 | 按种类回看卡片 |
| 登录 / 设置 | 邮箱密码；可选自备 Key 等 |

### D.1 主导航（已定）

- 底栏四项：**旅途 · 地图 · 图鉴 · 我的**  
- **默认打开：旅途列表**（主路径从旅途进相册上传）  
- **结算/开卡**为叠层或独立流程页，不占底栏  
- 登录、自备 Key、关于等进 **「我的」**

### D.2 图鉴 vs 旅途相册（已定）

- **A：**  
  - **旅途相册** = 某次旅行的照片时间线（分析中 / 待开包 / 已揭开；上传入口在此）。  
  - **图鉴** = 按**种类**的收集卡（N–XR 等），**跨旅途去重**；抽卡收集感落在这里。  
- 一条观察既进旅途相册，也（够格揭开后）更新图鉴条目。  
- **旅行套册**（成就）：主题册 + 规则槽点亮、整册灰→彩；配置驱动，见 [`features/旅行套册.md`](../features/旅行套册.md) 与 `SPEC.md` §7。

### D.3 地图默认视野（初步）

- 先按 **1：全部观察散点**；视野尽量框住用户的点（点很少时可世界概览 + 常驻底图防灰屏）。  
- 可后置「按旅途筛选」；非核心。

### D.4 未登录（后置备注）

- **愿望**：未登录可逛空壳/演示（地图底图、产品说明等）；上传、识图、图鉴与个人旅途数据要登录。
- **现状**：尚无社交/演示内容可逛，**本阶段不做**；有公开内容后再做门闸放宽。

### D.5 块 D 小结（均为可改草案）

| 项 | 初步约定 |
