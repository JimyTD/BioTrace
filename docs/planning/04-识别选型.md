## 1. 总原则

| 模块 | 态度 |
|------|------|
| 物种识别 | **禁止从零训练**；接入现成模型 / API |
| 世界地图 | **禁止自绘底图**；开源引擎 + 免费瓦片 |
| 旅途相册 / 抽卡 / 警示 | 业务逻辑自建；名录与规则用公开数据 |
| 花钱 | 尽量 $0；个人非营利 |

## 2. 关键事实：iNat 的识图不可接入

iNaturalist **没有**对外公开的 Computer Vision / 识图 API，其开放 API 只用于观察数据读写。**不要**再考虑「把 Seek/iNat 的识别当引擎嵌进来」——iNat 只能当体验标杆，不是可插拔组件。

## 3. 结论：走云多模态 API

| 角色 | 选择 | 理由 |
|------|------|------|
| 默认 | **Google Gemini**（免费层 Flash 系） | bakeoff 里大蚊稳到科；不硬编离谱种名 |
| 回退 / 国内直连 | **智谱 GLM 视觉** | 持久免费定位；国内直连；大蚊可到属 |
| 试过但未进正式矩阵 | 豆包（方舟）、通义 VL | 新人额度向，未测完 |

bakeoff 两张无 GPS 样张（实测目录 `model-bakeoff/results/`）：

| 样张 | Gemini | 智谱 `glm-4v-flash` |
|------|--------|---------------------|
| 大蚊向 | Tipulidae（科） | Tipula（属）+ 俗名略混 |
| 鱼向 | 弹涂鱼 / 虾虎鱼科级 | 斑鳢种级且置信 1.0（若为弹涂鱼则错认） |

→ 由此定下工程底线：**强制 JSON 输出 + 学名校验 + 属级成功线**，宁停在属也不硬凑种。识别层保持**可插拔**，厂商与模型可换。

## 4. 为什么不自托管 BioCLIP（重要的否决）

BioCLIP 2 效果确实过了个人验收（TreeOfLife-200M 训练、物种级基准强、可对齐生命树），但**没走**：

- 要自备 GPU / 推理机，部署与运维成本远高于调云 API；端侧塞不进
- 零样本仍要配分类名录，「缩名录做地点修正」还得自己搭
- 云 API 已能满足「属级成功线 + 地点先验」这条硬需求

若日后云 API 成本或可用性恶化，这条路仍可回头——但**不要**因为「开源模型听起来更专业」就重开。

## 5. 其它组件的一次性判断

- **旅途相册**：自建 `Trip ← Observation` 数据模型。可借鉴 TrailSnap 一类足迹相册的交互，但它是 **AGPL-3.0**，整仓 fork 有传染性许可风险——**借思路，别吞仓**。
- **EXIF 读写**：用成熟库，不自研。
- **入侵名录**：公开名录 + 观察点行政区匹配；**难点是数据整理的苦力活，不是算法**。
- **抽卡**：纯产品规则 + 图鉴表，不买组件。
- **专用免费识物 API**（Pl@ntNet 等）：植物侧专业但动物/全球体验割裂，**不做主路径**。

## 6. 成本态度

个人非营利、低频旅行使用下：地图 $0（署名义务）；云识图靠免费层 + 低频，量级可忽略；**不训练模型**。真正要盯的不是单次调用价，而是**是否被某家厂商的配额硬墙卡住**——故识别层双 Provider、地图有回落。
