> 阶段：第 3 步 · **已冻结**。云 API 路线最终被采用（Gemini 默认 / 智谱备选）；现行实现看 [`SPEC.md`](../SPEC.md) §1.1。  
> 与 [`archive/识别引擎证据包.md`](../archive/识别引擎证据包.md) §8（BioCLIP 自托管）并列备选，当时**未拍板**。  
> 用户观点（采纳）：自托管开源模型路径彼此大同小异，换更好开源权重通常只动推理层，替换成本低。

---

## 0. 和自托管路径怎么摆

| | **A. 自托管**（BioCLIP 等） | **B. 云 API**（豆包视觉等） |
|--|---------------------------|---------------------------|
| 你管什么 | GPU 机 / 自动启停 / 模型文件 | 账号、Key、Prompt、后处理 |
| 实时 | 要常开或吃冷启动 | **天然实时**（厂商池化） |
| 单张钱（个人） | 几分钱级（批量）～更贵（冷启动） | 通常 **分钱～更低**（视模型） |
| 地点怎么进 | GBIF 缩名录 + `--subset` | **Prompt 直接写坐标/地名**（简单） |
| 效果 | 你难例已满意；细粒度论文更强 | 你有豆包个案；细粒度公开榜弱于专用编码器风险 |
| 换引擎 | 换权重/镜像，API 形状可保持 | 换厂商要改 Prompt/解析，但外壳可抽象 |

**自托管换模型**：是的——App → 你的 `/identify` → 背后换 BioCLIP / 更新版 / 别的开源视觉模型，**前端几乎无感**；难在运维与钱，不在「换名字」。  
**云 API**：运维最轻，适合「先实时跑起来」；要靠结构化输出 + 校验管幻觉。

---

## 1. 这条路是什么（走通骨架）

```text
App 选图（带 EXIF）
  → 你的后端（便宜常开即可，甚至可 Serverless）
      → 组装 Prompt：图 + GPS/地名 + 日期 + 「请输出 JSON 分类链」
      → 调用云多模态 API（豆包 / 通义 VL / …）
      → 解析 JSON；用 GBIF 等校验学名、补全上级阶元
      → 低置信 / 校验失败 → 只展示到属 + 待确认
  → 返回 App
```

**没有 GPU 机。** 实时 = 等厂商推理延迟（通常秒级），不是等你开机。

## 2. 候选厂商（个人、国内友好优先）

| 优先级 | 服务 | 说明 |
|--------|------|------|
| **主候选** | **火山方舟 · 豆包视觉** | 你已有成功个案；国内访问好；Chat Completions 形态，图用 URL 或 base64 |
| 备选 | 通义千问 VL（百炼） | 同类多模态；可作第二源或比价 |
| 备选 | 其它国产 VLM | 按价/效果再测 |
| 低优先 | OpenAI GPT-4o 等 | 效果可作对照；费用与网络对你不一定友好 |

开通（豆包）：火山引擎 → API Key → 方舟创建 **视觉/多模态推理接入点** → 后端调 `chat/completions`（图文消息）。  
控制台入口以官网为准：https://console.volcengine.com/ark （方舟）

## 3. 成本直觉（云 API）

### 豆包视觉（历史公开口径）

- 输入约 **0.003 元/千 tokens** 量级（发布口径；以控制台实时价为准）  
- 宣传约 **1 元 ≈ 大量 720P 图** → 个人旅行年几百张，常见是 **几元～几十元/年**

### 粗算单张（数量级）

假设一张图 + 短 JSON 输出合计消耗约 1k～10k tokens（随分辨率/模型变）：

| 假设 | 单张约 |
|------|--------|
| 偏省 | **&lt; 0.01～0.03 元** |
| 偏多（大图+长思考） | **0.05～0.2 元** 量级仍可能 |

对比自托管 T4：批量时也可到「几分钱/张」，但 **实时常开或频繁冷启动** 会把总成本抬高；云 API 把「实时」的成本摊进厂商，对个人往往更省心。

## 4. 地理与其它辅助（API 路径怎么做）

比 BioCLIP **更直接**：

```text
系统/用户提示中写死：
- 拍摄坐标 / 地名（如井冈山，lat,lon）
- 拍摄日期
- 要求：只输出 JSON；界…种；给 confidence；不确定则 rank 停在属；
  优先考虑该地分布物种，勿编造外域种
```

可选增强（与自托管可共用后半段）：

| 步骤 | 作用 |
|------|------|
| GBIF 校验学名 | 防瞎编拉丁名；补全分类链 |
| 返回 top3 候选 | 让用户选，降低「唯一错误种」 |
| 温度调低 + JSON schema | 减胡说、稳解析 |

**弱点**：LLM 仍可能「自信地错」；地点在 Prompt 里是软约束，不如 `--subset` 硬砍候选集。可用「Prompt 地理 + GBIF 校验」双保险。

## 5. 工程要点（走通级，非完整方案）

1. **抽象识别接口**：`identify(image, lat, lon, time) → TaxonomyResult`  
   - 背后可接 `DoubaoProvider` / `BioClipProvider`，方便以后换。  
2. **强制结构化**：要 JSON（常见名、学名、各级阶元、confidence、notes）。  
3. **密钥只放服务端**：App 不直连方舟。  
4. **限流与失败**：超时、内容审核、余额；失败可降级「仅保存观察、稍后重试」。  
5. **日志**：留 prompt 版本与模型名，便于对比 BioCLIP。

## 6. 风险清单

| 风险 | 应对 |
|------|------|
| 幻觉种名 | JSON + GBIF 校验 + 属级成功线 |
| 涨价/改名/下线 | 抽象 Provider；备一条通义或自托管 |
| 隐私 | 图会出网到厂商；需隐私说明；敏感点可模糊坐标 |
| 效果不如 BioCLIP（细粒度） | 你的难例两边都测；可「API 实时 + 难例后用 BioCLIP 复核」 |

## 7. 和用户判断对齐

- 「部署开源模型路径大同小异，换模型简单」→ **同意**，记入架构原则：识别层可插拔。  
- 云 API 路径价值：**实时、零 GPU 运维、地点进 Prompt 简单、个人费用通常更低**。  
- 尚未要求二选一；可用同一批旅行照片做 **API vs BioCLIP** 对照后再定主路径。
