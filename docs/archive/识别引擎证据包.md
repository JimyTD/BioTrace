## 0. 先说清楚：两类东西不是一回事

| 类型 | 代表 | 擅长 | 短板 |
|------|------|------|------|
| **通用多模态 LLM** | 豆包视觉、GPT-4o、Gemini… | 看图说话、中文、易注入地点/时间、开发快 | 细粒度物种上常不如专用编码器；可能「自信地错」 |

## 1. BioCLIP：效果到底怎样？（有论文数字 + 可点 Demo）

### 1.1 它是什么

- 俄亥俄州立等团队的**生物图像基础模型**（MIT 开源）。  
- BioCLIP 2 训练数据 **TreeOfLife-200M**：约 **2.14 亿**生物图、约 **95.2 万**分类单元（GBIF / BIOSCAN / EOL / FathomNet 等）。  
- 项目页：https://imageomics.github.io/bioclip-2/  
- 论文：NeurIPS 2025，arXiv https://arxiv.org/abs/2505.23883  

### 1.2 公开基准（零样本物种分类准确率，%）

来源：BioCLIP 2 项目页表格（对比通用 CLIP / SigLIP / 上一代 BioCLIP）。**Mean = 各任务平均。**

| 模型 | NABirds | Insects | Insects2 | Camera Trap | PlantNet | Fungi | Rare Species | **Mean** |
|------|---------|---------|----------|-------------|----------|-------|--------------|----------|
| CLIP ViT-L/14 | 66.5 | 9.0 | 11.7 | 29.5 | 61.7 | 7.6 | 35.2 | **25.5** |
| SigLIP | 61.7 | 27.3 | 20.7 | 33.7 | 81.8 | 36.9 | 47.6 | **39.5** |
| BioCLIP（上一代） | 58.8 | 34.9 | 20.5 | 31.7 | 88.2 | 40.9 | 37.1 | **37.6** |
| **BioCLIP 2** | **74.9** | **55.3** | **27.7** | **53.9** | **96.8** | **83.8** | **76.8** | **55.6** |

读法（重要）：

- 相对通用 CLIP，平均大约 **+30 个百分点**（项目页表述）。  
- **不是**「所有昆虫都能 90%」：Insects 约 55%，Insects2 约 28%——细粒度昆虫仍然很难。  
- PlantNet / Fungi 很高，说明**植物/真菌侧很强**；动物侧看类群差很多。  
- 这些是**学术基准**，不等于你的旅行随手拍（光线、角度、死虫、背景杂）。

### 1.3 和「通用大模型识鸟」比：有一篇专门基准

**RealBirdID**（鸟类细粒度，对比 MLLM vs 编码器，CVPR 2026 相关公开材料 / arXiv:2603.27033）：

- 专用编码器里 **BioCLIP 系分类能力领先**；文中举例 BioCLIP-2 在极难多分类设定下属级约 **76%**、种级约 **41%**（数千种鸟的设定，种级很难是正常的）。  
- **Gemini-2.5 Pro 等 MLLM 在细粒度分类指标上整体落后 BioCLIP**（文中 IG：Gemini-2.5 Pro 约 57.7 vs BioCLIP 约 68.9——不同指标，方向是「专用更强」）。  
- **加分布区/地点信息后，各类模型都明显变容易**（平均 IG 大约 57→88）——这与你「井冈山先验很重要」完全同向。  
- MLLM 常见问题：过度自信、难「弃权」。

含义：**不能因为豆包比 Seek/生物记好看，就默认 LLM 一定赢过 BioCLIP**；也不能因为论文好看就默认 BioCLIP 在你手机照片上一定赢豆包。**必须同图对照。**

### 1.5 部署成本直觉（BioCLIP）

## 2. 豆包 / 火山视觉：能力与成本（能查到的公开信息）

### 2.1 能力：有「你的真实样本」，缺「物种专用论文」

| 证据类型 | 情况 |
|----------|------|
| 你的大蚊样本 | 豆包答对方向；Seek 门级失败——**这是强证据，但是 N=1** |
| 官方宣传 | 视觉理解、推理、旅游识菜单/建筑等；**不是**「对标 iNat 物种基准」的论文 |
| 物种细粒度公开榜 | 目前**没有**找到「豆包 vision vs BioCLIP vs iNat」的权威同榜；不能外推「豆包一定种级可用」 |

结论：豆包适合当 **MVP 候选 / 易用基线**，但要用 **一组你自己的旅行照片**做小样本验收，而不是默认永久方案。

### 2.2 成本（公开报道 / 文档口径；下单前以控制台为准）

历史发布口径（2024-12 Force 大会，多家媒体转述）：

- 豆包视觉理解：**约 0.003 元 / 千 tokens（输入）**  
- 宣传换算：**约 1 元可处理约 284 张 720P 图**（官方现场口径；实际随分辨率/模型变）

扣子/资源包文档中曾列出（积分制，常见 **1 积分≈0.001 元** 的换算口径，以官网为准）：

| 模型（文档名） | 输入 | 输出 |
|----------------|------|------|
| Doubao-vision-pro / 1.5-vision-pro | 3 积分/千 tokens | 9 积分/千 tokens |
| Doubao-vision-lite | 1.5 积分/千 tokens | 4.5 积分/千 tokens |

粗算（假设 1 积分=0.001 元，且一张图+短答大约消耗数千～一两万 tokens——**极粗**）：

| 用量 | 量级感觉 |
|------|----------|
| 一次旅行 50 张 | 往往 **几毛～几元** 量级 |
| 一年 500 张 | 往往 **几元～几十元** 量级 |
| 免费/试用额度 | 方舟/活动常见有一定 Token 赠送，**以你账号控制台为准**，第三方博客数字勿死记 |

**风险**：模型改名换代快（Seed 2.0 等），价目会变；物种场景 token 消耗取决于你是否要求长分类链输出。

### 2.3 其它 LLM（对照用，不强迫）

| 模型 | 备注 |
|------|------|
| GPT-4o / Gemini | 英文生态评测更多；RealBirdID 显示顶尖 MLLM 仍常落后专用编码器；海外 API 费用与网络对你不一定友好 |
| 通义 / 其它国产 VLM | 可作第二候选；同样需要你自己的照片小测 |

## 3. 和 iNat「体感」怎么对齐？

| 点 | 说明 |
|----|------|
| iNat 识图 API | **没有**公开 CV API → 不能接入当引擎 |
| iNat 强在 | 专用 CV + **地点加权** + 社区纠错 |
| 你若用 LLM | 必须自己做：地点进 Prompt、结构化输出、属级弃权、最好再挂分类库校验 |
| 你若用 BioCLIP | 更接近「专用编码器」路线；地点先验要**另做候选收缩**（论文也证明地点很有用） |

## 4. 当前不要求你拍板的结论

1. **问题 1（LLM）**：成本对个人旅行场景**大概率很便宜**；能力**有个案支持、缺系统物种基准** → 需要小样本实测协议，而不是现在锁定。  
2. **问题 2（BioCLIP）**：论文数字说明它在生物细粒度上**明显强于通用 CLIP**，且多项任务上**可强于通用 MLLM**；但昆虫种级仍难，且**必须你用大蚊图点 Demo 看一眼**。  
3. 合理下一动作不是选型签字，而是 **Bake-off（同图对照）**。

### 解读（产品层）

1. **分类链完整到种候选**：界门纲目科属种一路给出——正是你要的展示形态。  
2. **科/属高度一致**：Top1–4 均为大蚊科 Tipulidae，且多为大蚊属 *Tipula* → **满足「最粗到属」**；显著好于 Seek。

5. **与策略吻合**：成功线=属；种为加成；低置信展示候选列表而非唯一真理——BioCLIP 输出形态很适合。

## 7. BioCLIP 怎么用？开源吗？地点怎么进？（FAQ）

### 7.1 开源吗？

| 项 | 答案 |
|----|------|
| 模型权重 | **是**，Hugging Face：`imageomics/bioclip-2` |
| 训练/推理代码 | **是**，GitHub Imageomics/bioclip-2 |
| 许可 | **MIT**（对非营利/自用/二次开发都很友好） |
| 数据 | TreeOfLife-200M 等另有数据集条款，用模型推理一般按 MIT 权重即可 |

### 7.2 如何使用（三条路，由易到难）

**① 浏览器 Demo（你已在用）**  
https://huggingface.co/spaces/imageomics/bioclip-2-demo  

**② 官方封装库 pybioclip（推荐作为服务端推理入口）**  
文档：https://imageomics.github.io/pybioclip/

```bash
pip install pybioclip
# 默认即 BioCLIP 2；有 GPU 加 --device cuda
bioclip predict your.jpg --k 5 --device cpu
```

Python 亦可 `TreeOfLifeClassifier` / `CustomLabelsClassifier`。  
还可：`bioclip list-tol-taxa` 导出全部可预测分类名录（很大）。

**③ 底层 open_clip 直接加载**

```python
import open_clip
model, _, preprocess = open_clip.create_model_and_transforms(
    "hf-hub:imageomics/bioclip-2"
)
```

适合深度定制；App 侧通常是：**手机上传图 → 你的后端跑 pybioclip → 返回 JSON**。

### 7.3 能接受 GPS/地点等「物理信息」吗？

**模型本身：不能。**  
BioCLIP 是「图像 ↔ 分类文本」编码器，**没有**经纬度输入接口（不像把 GPS 写进豆包 Prompt 那样原生多模态）。

**工程上：能，而且应该做。** 官方 pybioclip 已提供「缩名录」能力，这就是地点修正的正路：

| 做法 | 怎么做 | 对应你的大蚊教训 |
|------|--------|------------------|
| **`--subset` 名录子集** | 用 CSV 只保留某 kingdom/…/species 集合再预测 | 井冈山 → 排除北美 *T. concava* 等 |
| **自定义 `--cls` 标签** | 只在「该地可能出现的种/属」里做 zero-shot | 地点列表来自 GBIF/名录 |
| **两阶段** | 先全球 TreeOfLife 出科/属 → 再用地区种名录精排 | 属稳、种靠地理 |
| **后处理降权** | 全球跑完后，按分布区把异域种分数打掉 | 简单但有效 |

地点名录数据源（免费、第 3 步可详谈）：**GBIF** 按坐标查 occurrence / 物种名录等。

**和 LLM 的对比**：豆包是「Prompt 里写井冈山」；BioCLIP 是「先查井冈山可能有哪些种，再只在这些标签里比对」。后者更可控、更贴科研习惯。

### 7.4 部署：不是官方远端 API（重要）

**pybioclip ≠「传一张图给别人服务器就完事」。**  
它是**跑在你自己机器上的库/命令行/Docker**。官方**没有**提供面向 App 的稳定商业识图 API（HF 上写明未部署 Inference Provider）。你用的 Hugging Face Space 只是**演示站**，不适合当生产后端。

| 形态 | 是什么 | 你要不要硬件 |
|------|--------|--------------|
| `pip install` / CLI | 本机 Python 调模型 | 本机 CPU 或 GPU |
| 官方 Docker `ghcr.io/imageomics/pybioclip` | 容器里跑同一套 CLI | 同上；Linux/Windows 可加 `--gpus all` |
| **你自己写的小 API**（Flask/FastAPI 包一层） | App 才「传图→拿 JSON」 | 跑 API 的那台机器要有算力 |
| HF Demo Space | 浏览器试用 | 不用；但不稳定、有限流，别当生产 |

典型自用链路：

```text
手机 App  --上传图片(+GPS)-->  你的后端 API  --调用-->  pybioclip/BioCLIP  (GPU/CPU)
                              （你写的几十行包装）
```

#### 硬件大概要多少（推理，非训练）

训练用了 32×H100——**与你无关**。你只做推理：

| 配置 | 体验粗估 |
|------|----------|
| **CPU only** | 能跑；单张可能数秒～几十秒，仅调试 |
| **笔记本/台式 6–8GB 显存**（如 3060/4060） | 个人 MVP 通常够用（batch=1） |
| **云 GPU 按需**（AutoDL / 租用 T4·3080 等） | 无本地卡时最省事；用时开机 |
| 磁盘 | 权重+缓存约数 GB～十余 GB 量级（含 TOL 标签嵌入缓存）；首次会从 HF 下载 |

更稳妥说法：先用 Docker/CPU 跑通一张图；要「秒级」再上消费级 GPU 或按小时租卡。

文档：Docker 说明 https://imageomics.github.io/pybioclip/docker/

#### 腾讯云跑推理大概多少钱？（刊例参考，下单以控制台为准）

对 BioCLIP 个人推理，**1×T4 16GB（如 GN7.2XLARGE32）通常够用**，不必上 V100/A100。

第三方汇总的腾讯云 **GN7（T4）刊例量级**（含活动价波动）：

| 规格（概念） | GPU | 按量约（元/时） | 包月约（元/月） |
|--------------|-----|-----------------|-----------------|
| 切分 vGPU 1/4～1/2 | 4～8GB | ~3–7 | ~900–2000 |
| **整卡 T4×1（推荐起步）** | 16GB | **~8–9** | **~2250–2500** |
| T4×1 更大 CPU | 16GB | ~12–19 | ~3600–5500 |

**场景粗算（按整卡 T4 ~8.5 元/时、包月 ~2400 元估）：**

| 用法 | 月费直觉 |
|------|----------|
| 7×24 一直开着 | **约 2000+ 元/月**（太贵，个人不划算） |
| 按量：每天开 1 小时识别 | ~8.5×30 ≈ **250 元/月** |
| 按量：一年旅行合计开机 20 小时 | ~8.5×20 ≈ **170 元/年**（外加磁盘等） |
| 关机不计费（若开通该策略） | 不用时成本接近磁盘/IP 小钱 |

对比：豆包视觉按「一张图几分钱」量级，个人低频往往 **一年几元～几十元**。  
故：腾讯云常开 GPU = BioCLIP 的主要「弱点」；**偶发出行按量开机**或**本地显卡/便宜 GPU 租用站**更贴「尽量不花钱」。

## 8. 备选路径：BioCLIP 自托管（实时向 · 走通级）

> 状态：**备选记录**，非最终锁定。用户实测识别满意；希望尽量**实时**使用；开机可用 API 自动完成，不必每次手登控制台。

### 8.1 形态（一句话）

轻量常开入口（便宜 CPU / 云函数）接 App → **按需拉起腾讯云 GPU** 跑 pybioclip → 空闲后 **关机不收费**；识别流水线带 **地理缩名录**。

```text
App（实时点识别）
  → 入口服务（常开、便宜）
      → 若 GPU 未开：云 API 开机（冷启动约数分钟）
      → GPU 上 BioCLIP +（可选）GBIF 缩名录
      → 返回分类链 / 置信
      → 空闲超时：关机不收费
```

### 8.2 单张成本直觉（粗）

- 计费基准：整卡 T4 刊例约 **8～9 元/时**（以订购页为准）。  
- 批量时约 **几分钱/张**；冷启动摊到单张会贵。  
- **实时**：要么接受偶发冷启动等待，要么提高开机时长（更贵），或常开（约两千+/月，个人一般不取）。

### 8.3 地理/辅助（走通，非完整方案）

BioCLIP 不直接吃 GPS。走通：

1. （可选）全球粗识别到科/属  
2. GPS → GBIF 等拉当地可能种/属名录  
3. `pybioclip --subset` / `--cls` 在名录内精排  
4. 种级低置信则展示到属 + 候选；允许手改  

多图、日期物候等可后加，同一骨架。

### 8.5 与豆包云 API 路径的关系

| | BioCLIP 自托管（本条） | 豆包等多模态 API |
|--|------------------------|------------------|
| 识别效果（你的难例） | 已满意 | 亦有个案，未系统对打 |
| 实时 | 可，但有冷启动或常开成本 | 天然实时、无自管 GPU |
| 钱 | GPU 时费；实时越勤越贵 | 按 tokens，个人通常更低 |
| 地点 | 工程缩名录 | Prompt 注入 |
