# 现成产品深挖：iNaturalist

> 阶段：第 1 步（现成产品是否满足）  
> 日期：2026-08-03  
> 前提：Seek 已判不可用；用户实测 iNat 识别较强；几乎不接受组合 App。

## 一句话定位

iNaturalist 是**全球公民科学观察平台**：把「某时某地遇见某个生物」记成可验证的观察记录，用 **AI 建议 + 社区鉴定** 把分类尽量推细，并汇入全球生命地图。  
它不是旅行相册，也不是私密回忆录产品。

## 和 Seek 的关键差别（解释你为何一个能用一个不能用）

| 点 | Seek | iNaturalist |
|----|------|-------------|
| 产品目标 | 儿童友好、当场认物种、徽章游戏 | 科学级观察记录与全球数据 |
| 精确位置 | 故意不存/不用于完整个人足迹 | **观察核心字段**：时间 + 地点 + 证据 |
| 识别是否用地点 | 仅模糊区域；你感觉「地点放不进去」 | **用地点与日期加权**视觉相似结果（附近出现过的物种上权） |
| 数据默认 | 本地、偏隐私 | **默认公开**（可逐条设 obscured / private） |
| 识别失败时 | 常停在很粗层级且难补救 | AI 建议 + **社区可继续改到属/种** |
| 账号 | 可不注册 | 需要账号 |

这与井冈山大蚊案例一致：带地点的识别，本就该比 Seek 强一截。

## 核心对象：Observation（观察）

一条观察通常包含：

1. **证据**：照片（可多张）或声音  
2. **时间**  
3. **地点**（坐标 + 精度圈；可从 EXIF / GPS / 地图手调）  
4. **鉴定（Identification）**：分类单元（可粗可细）  
5. **可选**：备注、野生/栽培、地理隐私、加入项目等

分类不是死标签：可沿生命树停在科/属/种；社区可追加更细鉴定。  
「Research Grade」≈ 社区对物种级达成一致且数据质量过关——偏科研，不是旅行产品概念。

## 识别能力（你最关心的部分）

### AI（Computer Vision）

- 训练自海量 iNat 观察与社区鉴定；模型定期更新（分类单元十万级量级，且持续涨）。  
- 够数据则学到**种**；种不够时会训练到**属/科**等更粗节点，避免乱猜种。  
- **空间-时间先验**：有位置/日期时，结合「附近曾出现」加权，抑制「长得像但地理不可能」的选项。  
- 输出是**建议列表**，不是唯一神谕；用户可选用某级分类。

### 社区

- 全球爱好者/专家可帮忙改鉴定——对难定昆虫尤其重要。  
- 代价：记录进入公共话语；要隐私需主动设 geoprivacy。

### 对照你的硬标准

| 你的标准 | iNat 匹配度 |
|----------|-------------|
| 海外可用 | **高**（全球覆盖是其强项） |
| 最粗到属、理想到种 | **较高**（AI + 地点 + 社区；种级不保证） |
| 分类学链路 | **有**（生命树 / taxon 页面可看上级阶元） |
| 单 App | 识别+落点+个人观察地图：**有**；旅行相册：**无** |

## 个人回看：有什么、没有什么

### 有（偏「自然观察档案」）

- **My Observations**：列表 + **地图打点**（个人观察分布）  
- **Calendar**：按日看记录密度  
- **Life List**：一生见过的物种清单（可按类群/地点筛）  
- **Explore / 筛选**：按地点、分类、日期查自己的观察  
- **Journal**：文字日志（偏博客，不是精美相册）  
- **Projects**：主题合集（活动/区域/课题），不是「云南之旅画册」  
- **导出**：可导出自己的数据（CSV 等）——对非营利自用有价值

### 名字像旅行、实际不是：Trips

- iNat 有 **Trips**，但是**科研采样努力 / 有无数据（presence-absence）**工具：搜索时段、搜索半径、目标物种列表。  
- 社区也认为该功能偏冷门、体验不完整。  
- **不要当成旅行相册或足迹叙事。**

### 没有（相对你的灵感）

- 以「一次旅行」为容器的精美回忆叙事  
- 相册时间轴 + 旅程轨迹的沉浸回看  
- 把生物图鉴做成个人旅行作品集的一等体验  
- 默认私密的个人图鉴空间（平台基因是分享与科学）

## 隐私与「非营利自用」注意点

- 观察**默认公开**；精确坐标默认可见。  
- Geoprivacy：`open` / `obscured`（约 0.2° 网格模糊）/ `private`（对外隐藏地理）。  
- 不能一劳永逸设「默认全部 private」（平台鼓励分享；需逐条或批量改）。  
- 濒危物种常有 **taxon geoprivacy** 自动模糊。  
- 对你：若只想自己留档，iNat 能用但**别扭**——一直在「公共科学平台」里做私人相册。

## 第 1 步对 iNat 的阶段性判定

### 已通过（相对 Seek）

- 识别主路径可用；**地点进入识别**符合你的使用场景。  
- 全球/海外、分类树、个人观察地图打点，单 App 内都有。

### 未通过（相对完整灵感）

- **没有旅行相册 / 旅程叙事**——你已明确感知到的缺口。  
- 产品灵魂是公民科学，不是旅行回忆录；硬改心智成本高。

### 结案含义（草案）

在「几乎不接受组合」前提下：

- iNat **不能**作为「完美满足全部灵感」的终局产品。  
- iNat **可以**作为：  
  - 识别质量的**现实标杆**（什么叫够用的属/种建议）；  
  - 以及：若第 2 步把「旅行相册」降为非必须，则它可能升格为「凑合长期单用」。  

是否进入第 2 步，取决于你对下面问题的答案：

> **没有旅行相册，只靠 iNat 的观察列表 + 地图打点 + Life List，你是否愿意长期只使用它？**

- 愿意 → 第 1 步可终止于 iNat  
- 不愿意 → 第 1 步结案为「无完美现成单品」，进入第 2 步需求辨明（默认倾向自研/二次开发）

## 建议你再确认的 3 个体验点（仍属第 1 步）

1. 井冈山大蚊：iNat 建议停在哪一级？有没有用到地点？  
2. 打开「我的观察」地图：一趟旅行的点看完是否有旅程感，还是只有散点？  
3. 隐私：你能否接受默认公开，或每次/批量设 obscured？

## 用户追加小主意 vs iNat（2026-08-03）

用户正在试用，并提到两个额外想法。此处只做「现成是否满足」，不定需求优先级。

### 1）入侵物种警示（例：非洲大蜗牛）

| 点 | 说明 |
|----|------|
| iNat 有什么 | **Establishment Means**：某地对某分类单元标 `native` / `introduced` / `endemic`。引入种观察上可出现粉色感叹号徽章 |
| iNat 刻意没有什么 | 官方**不用 invasive（入侵）**一词——认为带生态危害判断、定义不统一；只标「是否由人类引入」 |
| 和你想要的差距 | 你要的是面向旅行者的**警示感**（危险/危害/别乱摸别扩散）；iNat 给的是严肃的「引入状态」元数据，不是消费级警告卡 |
| 阶段判断 | **部分数据基础可能在，产品形态不满足** |

### 2）按拍到的动物抽卡 / N–UR 收集感

| 点 | 说明 |
|----|------|
| iNat | **明确不做**徽章/成就向游戏化；团队认为会激励刷低质量数据。游戏化被放到 Seek |
| Seek | 有徽章、挑战、类群收集进度——仍是「成就徽章」，**不是** N/R/SR/UR 抽卡稀有度 |
| 和你想要的差距 | 年轻人向的卡牌稀有度、收集癖、抽卡反馈 → 现成两款都**不提供** |
| 阶段判断 | **现成产品不满足**；若你坚持，会成为自研差异点（第 2 步再定必须/好玩） |

### 对第 1 步的含义

iNat 更像「严肃科普 + 公民科学」；旅行相册、入侵警示体验、抽卡收集感都不在其产品基因里。  
继续认真试用即可；这些小主意先记为**潜在差异点**，等你对「能否长期单用 iNat」表态后再进入第 2 步统一辨明。
