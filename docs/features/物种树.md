## 拍板铁律

本文件记的是**用户已经反复强调过的话**。它们不是待议选项，不是待批准方案，是已经生效的要求。

三条规矩：

- 动这棵树之前，先过一遍本文件。
- 这里的条目**不要再拿去问一遍**。问就是没当真。
- 只做半条比不做更糟 —— 半条会让人以为已经做完了。

### 1. 第一屏不看真实数据

> 「第一屏，也就是树-各界这屏 不需要真实数据 反正你点进去实际上也是有动画的，不需要真的一定要，打比方说动物种类多，枝条就茂密 这个你理解吗 纯为了美观考虑，反正进去枝叶会有真实数据的」

含义：全树看各界这一屏的**形态**（分叉数、分叉深度、枝长、叶量）全部写死，只为好看。真实条数、收集量都不参与。点进某一界之后才是真实数据，两屏之间有生长动画兜着，**不必一一对应**。

验收：**空收集与满收集，叶数必须完全一样**，只有颜色（点亮）不同。不一样就是没脱钩。

已落地：`OV_B`（每枝固定几根可见子枝）、`OV_D` / `OV_LMIN`（分形深度写死）、`decoFillOn`（不够就补装饰枝）、超出的子枝按 `OV_HIDE` 塌起来。

### 2. 竖屏

> 「你这个手机分辨率是横屏的啊 不对 搞竖屏示意就行了」

这是个竖屏手机应用。**所有示意、演示、截图一律 390×844 竖屏**。窗口装不下就整体等比缩放，不许把画面压成窗口的形状 —— 压扁之后看到的树高宽比是假的，据此做的判断也是假的。

### 3. 饱满圆润的来路：六杈、六色、叶成簇

> 「之前能够显得饱满、圆润、完整是因为有六个树杈，颜色六种 尽管高低不一致，但是衬托在一起非常好看」
> 「叶是链不是簇 这个可能是我觉得最大的关键」
> 「问题不在你说的宽度，在枝条光秃秃的……你就算是把树枝宽度拉满一屏 它也是光秃秃的」

三件事，都是"饱满圆润"的构成，不是可选项：

1. **六个树杈**。三主枝各占两个枝条，画面上六杈。
2. **六种颜色衬托**。这不只是在描述 v1 —— 单一视角能看到几个色块，直接决定这一屏好不好看。同界两支相邻会让任一角度只看到两个界的颜色。
3. **叶成簇，不成链**。冠的轮廓由**叶**决定，不由枝决定。叶沿枝排成一条链就是梳齿，叶量再翻几倍也只让穗更长。参照 v2 原型的原话：「种紧贴枝端聚成叶簇，避免枝与点之间出现空白（秃枝）」。

参照物：`prototypes/clear-tree/v1-canopy.html`（六杈六色、絮状冠）、`v2-roots.html`（枝叶与绒球质感）。

### 4. 中枝保留在主干腰上

> 「其实共创者更偏爱有中枝的方案」「可以废除方案2了，之后的比较、修改、讨论中不再带它」

主干腰上那一档（色藻 / 原生动物）留着。**方案二（中枝入冠）09-04 废除**，代码、演示页、讨论里都不再出现。它显得像瘤子是因为太稀，不是因为挂在腰上；参照 v2 原型的两颗小绒球。

### 5. 三个界等量

> 「我需要好看不需要一定要搞什么随机差异 你自己看看就知道，现在动物明显比其他两个枝 长、大」

动物 / 植物 / 真菌在冠上**同档、同拆分、体量相同**。谁的门多、收得多都不影响它在画面上的体量 —— 这是第 1 条的直接推论。

要的是**界与界之间**等量，不是六支枝几何全等。同一个界的两支可以一长一短（`ARM_JIT`，两支之和三界都是 2.00），子枝规模不跟着抖 —— 那样短的那支会在 `OV_LMIN` 处早收一层，真的变稀。六杈全等的代价是冠顶变成六个等高的尖围成一环，环心空。

## 附：冠为什么不圆 —— 分三层

把三件独立的事拧成一个"密度"旋钮调就会绕圈。三层各有各的量化口径，改哪层就量哪个数。

量法（`.shot/` 下的临时脚本，不入库）：逐列取最高的树像素得**上轮廓**；取冠内孤立连通块的中位面积得**一片叶多大**；树像素占画面、占自身包围盒得两种**填充率**。截图必须按自转相位连截几张。

**第一层 · 叶摊在多少个位置**（已解决）

| | v1 原型 | 最早 | 现在 |
|---|---|---|---|
| 枝 | 16914 | 4422 | 21370 |
| 末梢（叶簇位置） | ~1.4 万 | 2060 | ~1.1 万 |
| 叶 | 14.2 万 | 10.9 万 | 19.9 万 |
| 每末梢叶数 | ~10 | 53 | 18 |

53 片挤一簇 = 密实的球，球间必然有缝；十来片松松一簇、上万簇彼此搭接才是连续冠面。

**第二层 · 颗粒粗细**（已解决，曾经调反）

屏幕上一片叶的实测直径（`grain.mjs`，竖屏 390×844）：v1 2.5px，曾一度 3.4px，现在 2.4px。

**同样的覆盖率下，「多而小」是簌簌的絮，「少而大」是一颗颗糖球**。抬 `LEAF_R` 治"碎点"方向是反的。另一个坑：叶簇三个尺度都按枝长取比例，而我们的末梢比 v1 短三分之一，照抄 v1 系数簇只有它四成体积 —— 要对齐**绝对**尺寸（`CLUMP_R0` / `CLUMP_RD` / `CLUMP_EL0` / `CLUMP_ELD`）。

## 附：地面、根系、中枝（09-07）

- **中枝 1.5 倍是放大镜，不是长得更多**。`OV_LMIN` 是绝对长度，放大就会多分一层 —— 那是结构变了。所以中枝收尾阈值同乘 `MID_K`（`lminOf`），改完叶数一字不差。放大要连宽度一起。
- **根系压扁不能只按比例缩竖直分量**。根系张角 80°+，按比例缩会留正的竖直分量，枝从土里钻出来 —— 要取 `-abs()`。叶簇同理，整簇翻到 `GROUND_Y` 以下。
- **地面为什么"没了"**：半径原本按树冠包围盒算，而点数固定 `GND_N` —— 冠每宽一点，面密度掉平方。已改成按 `TRUNK_H` 写死，比根系铺得开、渐隐只留最外圈、亮度比背景低一档偏土色。
- 排查靠把地面临时染成红色一次定位。**下次先染色，别猜。**

## 附：主干缩到 2/3（09-07）

- 主干的**可见高度**和**尺度基准**必须是两个量。冠的枝长、中枝、根系、地面、`OV_LMIN` 全以 `TRUNK_H` 为基准，直接改会把定稿的树冠一起缩小。新增 `TRUNK_VIS = TRUNK_H * 2/3`，只喂主干那一段。
- **缩了主干必须重排中枝**。中枝连叶竖直跨度约 50，主干缩完只剩 88，`TIER2_AT` 从 `0.70` 重分到 `0.52`。这个比例跟着 `TRUNK_VIS` 走，以后动主干长度得一起重算。

## 附：总览压瘦与竖屏收窄（现行做法）

- **总览压瘦**（H）：总览时把左右（X/Z）压瘦、高度不变，让竖屏竖向重新撑满；横屏不压；展开后撤掉。系数见 `TreeScene` `spreadK()` 类逻辑（`max(0.62, min(1, 0.62+(asp-0.45)*0.62))`）。
- **竖屏收窄扇形**（I）：竖屏把张角收到约 0.62 倍，同时子枝加长 `1 + (1-张角系数) × 0.55`（约 1.21 倍），补回收窄后铺不开的感觉；横屏不改。
