# Web 皮肤主题

> **状态：机制已落地，皮肤只剩一套**（默认「日光图版」`daylight`，表现正在重做）。原为 `docs/06 §10`，2026-08-10 拆出为独立专题。  
> 2026-08-25 由「日光胶片」更名为「日光图版」：美术改走 19 世纪博物图版（素版线刻 / 手工上色彩版），胶片一说已名不副实。`daylight` 这个 id 不变。  
> 「潮间带」`tide` 与「暗房」`darkroom` 已于 2026-08-25 退役删除，理由见 [`品牌叙事.md`](./品牌叙事.md)。  
> 与文案包同思路：**表现集中、流程页不写死品牌色**。  
> 强制约束另见 [`.cursor/rules/web-themes.mdc`](../../.cursor/rules/web-themes.mdc)。

皮肤不只换 token：版式 class（顶栏、封面旅途卡、相册 film-grid、细底栏）属 [`styles.css`](../../apps/web/src/styles.css) 结构层；换皮改 token，**不要**复制 `pages/*`。

一套皮肤由四件东西组成，缺一不可地都归 `themes/` 管：

1. **配色 token** — `themes/<id>.css` 的 `[data-theme="<id>"]`
2. **资源包** — `public/{volumes,trips,settle,shell}/<id>/`，经 helper 引用
3. **明暗 scheme** — `THEME_META` 里声明 `light` / `dark`，写进 `<html data-scheme>` 与 `color-scheme`
4. **包装用词** — `THEME_META.voice` 指向 `packages/messages` 的覆盖表（见 §5）

## 1. 文件职责

| 路径 | 职责 |
|------|------|
| [`apps/web/src/themes/core.ts`](../../apps/web/src/themes/core.ts) | `ThemeId` / `THEME_IDS` / `THEME_META`、`initTheme` / `applyTheme`、资源域回退、localStorage `bt_theme` |
| [`apps/web/src/themes/index.ts`](../../apps/web/src/themes/index.ts) | 统一导出入口 |
| [`apps/web/src/themes/daylight.css`](../../apps/web/src/themes/daylight.css) | `[data-theme="daylight"]` 下全部设计 token |
| [`apps/web/src/styles.css`](../../apps/web/src/styles.css) | 布局与组件 **结构**；只引用 `var(--*)`，不写品牌色十六进制 |
| [`apps/web/src/main.tsx`](../../apps/web/src/main.tsx) | `import` 各皮肤 CSS + `initTheme()` |

## 2. 语义 token（皮肤必须覆盖）

新增皮肤时，至少提供与 `daylight.css` 同名的变量，否则结构样式会缺色：

- 字：`--font-sans`、`--font-brand`
- 底与字色：`--bg0`、`--bg1`、`--ink`、`--muted`、`--line`、`--bg-atmosphere`
- 品牌与行动：`--accent`、`--accent-soft`、`--accent-border`、`--accent-border-strong`、`--cta`、`--cta-ink`、`--secondary`
- 底栏：`--nav-bg`、`--nav-active-bg`、`--nav-active-ink`（激活态勿复用冷绿 soft）、`--nav-texture`（可选；日常页默认不用贴图）
- 状态：`--warn`、`--danger` 及 soft/line/badge 配套
- 表面：`--card`、`--card-muted`、`--input-bg`、`--surface-wash`、`--modal-bg`、`--modal-scrim`、`--shadow`
- 圆角：`--radius-sm` / `--md` / `--lg` / `--btn`
- 地图：`--map-dot`、`--map-dot-selected`、`--map-dot-ring`、`--map-dot-border`
- 开包垫：`--photo-mat`（未出图 / 照片窗深底）
- 氛围底：`--bg-atmosphere`（日常页用颜色和光，不贴纸的照片）
- 稀有度：`--rarity-{N,R,SR,SSR,UR,LR,XR}-{bg,fg}` + `--rarity-*-seal` / `--rarity-*-seal-ink`；色阶灰→亮蓝→亮紫→亮金→刺红→彩虹(LR)→霓虹洋红；XR 另用 `rarity-seal-xr.svg` 异形章
- 名录标签：`--list-tag-{class_i,class_ii,sanyou,extinct}-{bg,fg}`（引入种复用 `--warn-*` / `.intro-tag`）
- 徽章与光晕：`--rarity-LR-badge`（LR 徽章渐变）、`--volume-complete-glow`（成册弹层外发光）、`--danger-ink`（危险按钮字色）
- 纸纹：`--page-texture` / `--page-texture-size` / `--page-texture-opacity` / `--page-texture-blend`、`--nav-texture` / `--nav-texture-size`

若结构样式需要新视觉维度，**先**在 `styles.css` 改用新 `var(--…)`，**再**在每个已登记皮肤里赋值——不要只在某一皮肤或某一页面写死。

## 2.1 资源包与缺图回退

四个主题化资源域，目录一律 `public/<域>/<themeId>/`：

| 域 | helper | 文件 |
|----|--------|------|
| `volumes` | [`volumeAssets.ts`](../../apps/web/src/themes/volumeAssets.ts) | `cover-<volumeId>.png` ×3、`ceremony-{slot,complete}.png`、`stamp-frame.svg`、`seal-complete.svg` |
| `settle` | [`settleAssets.ts`](../../apps/web/src/themes/settleAssets.ts) | `pack-bg.png`、`pack-sealed.png`、`photo-frame.svg`、`rarity-seal[-xr].svg` |
| `trips` | [`tripAssets.ts`](../../apps/web/src/themes/tripAssets.ts) | `cover-frame.svg`、`film-frame.svg` |
| `shell` | [`shellAssets.ts`](../../apps/web/src/themes/shellAssets.ts) | `page-texture.jpg` |

所有 helper 都走 `themeAssetBase(domain, id)`：**皮肤在 `THEME_META.assets` 里没声明某个域，就自动回退 `DEFAULT_THEME` 的目录**。
所以新皮肤可以先只出一部分图上线，不会满屏破图；等资源补齐再把域加进 `assets`。
反过来，声明了却没放文件仍是 404 —— 声明即承诺。

文件名与分层见 [`套册美术分层.md`](./套册美术分层.md)。同名同几何是硬要求：邮票内窗 8% inset、开包框 6% inset，跨皮肤必须一致，否则换皮会错位。

## 2.2 壳纸纹

`--page-texture` 由 `.app-shell::before` 平铺消费，`--nav-texture` 由顶栏与底栏消费，默认 `none`。  
`daylight` 目前两者都是 `none`，纸感只靠 `--bg-atmosphere`——`shell/daylight/page-texture.jpg` 已备好但未启用。

## 3. 如何新增皮肤（清单）

1. 新建 `apps/web/src/themes/<id>.css`，选择器 `[data-theme="<id>"] { … }`，填满 §2 变量。  
2. 备资源包 `public/<域>/<id>/`（文件名对齐 daylight）。只出一部分也行——见 §2.1 回退。  
3. `themes/core.ts`：把 `"<id>"` 加入 `ThemeId` 与 `THEME_IDS`，并在 `THEME_META` 登记 `scheme` / `assets` / `voice`。  
4. `main.tsx`：`import "./themes/<id>.css"`。  
5. `packages/messages`：加 `theme.<id>` 与 `theme.<id>Hint`（外观页读这两个 key）。要换包装用词再按 §5 加 voice。  
6. 若该皮肤要专用 Web 字体：改 `index.html` 的 fonts link（或多皮肤时按需加载，避免无关字体）。  
7. 用户在「我的 → 外观」切换（`applyTheme`）；**不要**为换皮复制页面组件。  
8. 验收：默认 `daylight` 仍正常；切到新皮肤后按钮/导航/稀有度徽章/地图点/弹层均有色且无大片未定义回退；深色皮肤额外查照片垫、地图简图与弹层遮罩。

## 4. 明确不做

- 不为换皮分叉 `pages/*` 业务逻辑或复制整页。  
- 不把长中文或品牌色写进 API 路由。  
- 不在未登记皮肤 id 时写入 `localStorage`（`isThemeId` 会拒掉）。  
- 不在 `THEME_META.assets` 里声明没有实际文件的域。

## 5. 包装用词（voice）

同一个功能，不同皮肤可以有不同说法：一套说「专家鉴定中」，另一套可以说「显影中」。
这层落在 `packages/messages/src/voices/`（暂无覆盖表，加第二套皮肤时新建），一个皮肤一张，
类型是 `Partial<Record<MessageKey, string>>`——只写与基础文案不同的 key，其余自动落回 `zh.ts`。

- `applyTheme` 会调 `setMessageVoice(THEME_META[id].voice)`，切皮肤即换词
- 覆盖表里的 key 必须已存在于 `zh.ts`，否则类型不过
- 服务端从不调 `setMessageVoice`，API 恒用基础文案
- 当前只有 zh；加语言时按语言分表
- **只换说法，不换含义**：状态码、功能、流程一律不动（见 [`品牌叙事.md`](./品牌叙事.md) §2）

## 6. 后置

- 默认皮肤表现重做：包装层（灰框 / 牛皮纸封缄）与稀有度色阶目前和铜版画册皮不是同一套语言。  
- 开包仪式目前只能换贴图、换不了动作（阶段与运动写死在结算组件里）；要支持「不同皮肤不同包装」需把动作也做成皮肤可选。  
- 手绘级册皮/开包壳（生成图可继续换）；更多套册策展。  
- 位图单张 1~2MB，后续统一压缩并出 WebP。  
- `public/themes/preview.html` 的 token 目前是手抄的，与 `themes/*.css` 有漂移风险；可考虑由脚本生成。
