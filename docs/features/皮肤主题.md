# Web 皮肤主题

> **状态：两套皮肤，默认「清透」`clear`**。原为 `docs/06 §10`，2026-08-10 拆出为独立专题。  
> 2026-08-26 备选皮肤由「灯箱」`lightbox` 改为「清透」`clear`：**这套没有世界观，只有观感**——浅冷白底、照片带暖白边贴上去、圆角柔影大留白、界面轻到几乎不见，淡彩只做小面积。灯箱那套设定（随队记录、把片子推上灯箱）连同它的 voice 文案一并退役；当初真正被认可的只是照片那一半，留下了。旧 id 在 `core.ts` 的 `LEGACY_THEME_IDS` 里映射到新 id，本机或账号里存过 `lightbox` 的不会掉回默认。  
> 同日「日光图版」由「日光胶片」更名：美术走 19 世纪博物图版（素版线刻 / 手工上色彩版）。`daylight` 这个 id 不变，现为备选。  
> 2026-08-31 用户默认改为 `clear`。资源域缺图仍回退 `daylight`（`ASSET_FALLBACK_THEME`），因为清透故意不备 settle / shell。  
> 「潮间带」`tide` 与「暗房」`darkroom` 已于 2026-08-25 退役删除，理由见 [`品牌叙事.md`](./品牌叙事.md)。  
> 与文案包同思路：**表现集中、流程页不写死品牌色**。  
> 加功能时的强制清单见 [`.cursor/rules/web-themes.mdc`](../../.cursor/rules/web-themes.mdc)（短规则，只留对各皮肤都成立的条目）。本文是细则、token 表与已知坑。

皮肤不只换 token：版式 class（顶栏、封面旅途卡、相册 film-grid、细底栏）属 [`styles.css`](../../apps/web/src/styles.css) 结构层；换皮改 token，**不要**复制 `pages/*`。

一套皮肤由五件东西组成，都归 `themes/` 管：

1. **配色 token** — `themes/<id>.css` 的 `[data-theme="<id>"]`
2. **资源包** — `public/{volumes,trips,settle,shell,collection}/<id>/`，经 helper 引用。`collection` 目前只有清透备了文件；日光没有，helper 返回 `null`，不回退。
3. **结构摆放** — 零件节点由 `styles.css` 一次渲全，各皮肤用 CSS 决定摆在哪（见 §2.3）
4. **明暗 scheme** — `THEME_META` 里声明 `light` / `dark`，写进 `<html data-scheme>` 与 `color-scheme`
5. **包装用词** — `THEME_META.voice` 指向 `packages/messages` 的覆盖表（见 §5）

## 2. 语义 token（皮肤必须覆盖）

新增皮肤时，至少提供与 `daylight.css` 同名的变量，否则结构样式会缺色：

- 字：`--font-sans`、`--font-brand`、`--font-meta`（日期/编号这类标注字；不分标注体的皮肤指回 `--font-sans`）
- 底与字色：`--bg0`、`--bg1`、`--ink`、`--muted`、`--line`、`--bg-atmosphere`
- 品牌与行动：`--accent`、`--accent-soft`、`--accent-border`、`--accent-border-strong`、`--cta`、`--cta-ink`、`--secondary`
- 底栏：`--nav-bg`、`--nav-active-bg`、`--nav-active-ink`（激活态勿复用冷绿 soft）、`--nav-texture`（可选；日常页默认不用贴图）
- 状态：`--warn`、`--danger` 及 soft/line/badge 配套
- 表面：`--card`、`--card-muted`、`--input-bg`、`--surface-wash`、`--modal-bg`、`--modal-scrim`、`--shadow`
- 圆角：`--radius-sm` / `--md` / `--lg` / `--btn`
- 地图：`--map-dot`、`--map-dot-selected`、`--map-dot-ring`、`--map-dot-border`
- 开包垫：`--photo-mat`（未出图 / 照片窗深底）
- 氛围底：`--bg-atmosphere`（日常页用颜色和光，不贴纸的照片）
- 稀有度：`--rarity-{N,R,SR,SSR,UR,LR,XR}-{bg,fg}` + `--rarity-*-seal` / `--rarity-*-seal-ink`；色阶灰→亮蓝→亮紫→亮金→刺红→彩虹(LR)→霓虹洋红；XR 另用 `rarity-seal-xr.svg` 异形章
- 名录标签：`--list-tag-{class_i,class_ii,sanyou,extinct}-{bg,fg}`（引入种复用 `--warn-*` / `.intro-tag`）
- 徽章与光晕：`--rarity-LR-badge`（LR 徽章渐变）、`--volume-complete-glow`（成册弹层外发光）、`--danger-ink`（危险按钮字色）
- 相册格投影：`--film-tile-shadow`（片框/胶片格压在底上的影，冷暖跟着底走）
- 纸纹：`--page-texture` / `--page-texture-size` / `--page-texture-opacity` / `--page-texture-blend`、`--nav-texture` / `--nav-texture-size`

若结构样式需要新视觉维度，**先**在 `styles.css` 改用新 `var(--…)`，**再**在每个已登记皮肤里赋值——不要只在某一皮肤或某一页面写死。

## 2.1 资源包与缺图回退

五个主题化资源域，目录一律 `public/<域>/<themeId>/`。日光备齐 volumes / trips / settle / shell；清透只声明 volumes / trips / collection。`collection` helper **不回退日光**——日光没有这些图，凑过去只会 404。

| 域 | helper | 文件 |
|----|--------|------|
| `volumes` | [`volumeAssets.ts`](../../apps/web/src/themes/volumeAssets.ts) | `cover-<volumeId>.png` ×3、`cover-<volumeId>-colored.jpg`（集齐换的那张）、`plate-<volumeId>-<slotId>.png`（空槽）、`ceremony-{slot,complete}.jpg`、`stamp-frame.svg`、`seal-complete.svg` |
| `settle` | [`settleAssets.ts`](../../apps/web/src/themes/settleAssets.ts) | `pack-bg.png`、`pack-sealed.png`、`photo-frame.svg`、`rarity-seal[-xr].svg` |
| `trips` | [`tripAssets.ts`](../../apps/web/src/themes/tripAssets.ts) | `cover-frame.svg`、`film-frame.svg`、`frontispiece.jpg` |
| `shell` | [`shellAssets.ts`](../../apps/web/src/themes/shellAssets.ts) | `page-texture.jpg` |
| `collection` | [`collectionAssets.ts`](../../apps/web/src/themes/collectionAssets.ts) | 清透：`tree-door.png`（图鉴门）、`tree-n1.png`–`tree-n4.png`（1–4 个孩子的仰视）、`tree-crown.png`（再多走进树冠） |

`ASSET_DOMAINS` 仍是 volumes / trips / settle / shell 四项，日光的 `THEME_META.assets` 用它。不要把 `collection` 加进去，否则日光会声明一个没有文件的域。

所有 helper 默认走 `themeAssetBase(domain, id)`：**皮肤在 `THEME_META.assets` 里没声明某个域，就自动回退 `ASSET_FALLBACK_THEME`（日光）的目录**，不是用户默认。用户默认是清透，清透故意不备 settle / shell，回退到它自己会 404。
`collection` 是例外：未声明该域时 helper 返回 `null`，页面不要去拼 `<img src>`。
所以新皮肤可以先只出一部分图上线，不会满屏破图；等资源补齐再把域加进 `assets`。
反过来，声明了却没放文件仍是 404 —— 声明即承诺。

文件名与分层见 [`套册美术分层.md`](./套册美术分层.md)。同名同几何是硬要求：邮票内窗 8% inset、开包框 6% inset，跨皮肤必须一致，否则换皮会错位。  
`pack-sealed.png` 另有一处硬几何：窗口必须对齐 `styles.css` 里 `.settle-stage.is-sealed .settle-photo-mat` 的 `top 23.9% / right 36.1% / bottom 24.6% / left 16.3%`，错了照片就跑到壳外面。这只对用默认开包舞台的皮肤有效——`clear` 走 `settleStage` 槽位整只换掉了舞台，所以它连 `settle` 域都没声明。

**声明域之前先确认真有人读**：`clear` 一度声明了 `settle`（文件是齐的，从灯箱改名搬过来），但它既换了开包舞台又换了稀有度，那个域一张图都读不到，等于白白多打包一份。同理它也不声明 `shell`（`--page-texture: none`）。

## 2.2 壳纸纹

`--page-texture` 由 `.app-shell::before` 平铺消费，`--nav-texture` 由顶栏与底栏消费，默认 `none`。  
两套皮肤目前都是 `none`：`daylight` 的纸感只靠 `--bg-atmosphere`（`shell/daylight/page-texture.jpg` 已备好但未启用），
`clear` 则是**故意不铺**——那套风格的底就该是干净的，加一层纹理立刻把「清透」压成「有质感的纸」。
灯箱时期铺过 `multiply` 0.09 的磨砂扩散层，随设定一并退役。

## 2.3 结构层：零件常在，位置由 CSS 决定

token 只能换颜色，换不了摆放。2026-08-25 灯箱翻车就翻在这儿：示意稿里说明字是打在卡纸下沿上的，
而 DOM 里根本没有「下沿」这个节点，说明是片框的兄弟节点、排在框外，CSS 再怎么写也搬不进去。

补法照 CSS Zen Garden：**零件节点一次渲全，摆在哪、哪一段亮，交给 `[data-theme]` 下的 CSS**。
皮肤之间的差别优先靠摆放实现，不靠分叉组件。四个面（旅途相册格 / 旅途封面 / 套册格子 / 开包舞台）都已搬完。

### 共用的卡纸栅格

四个面用 `styles.css` 里同一段声明，三列五行，区域名：

```text
lip-tl    lip-top      lip-tr
lip-left  window       lip-right
lip-bl    lip-bottom   lip-br
below     below        below
foot      foot         foot
```

前三行是卡纸本身，`below` / `foot` 给说明和标注各留一行。跨格用线名 `mount-start` / `mount-end`
（整张卡纸）、`win-start` / `win-end`、`below-start` / `below-end`（卡纸外整段）。

四边宽与窗口行高由这几个变量给，皮肤改边只动它们：

| 变量 | 作用 |
|------|------|
| `--mount-lip-top/right/bottom/left` | 卡纸四边宽。改这个就换了卡纸比例 |
| `--mount-window-h` | 窗口行高。缺省 `auto`，窗口按自己的 `aspect-ratio` 定高 |
| `--mount-caption-gap` | 说明与卡纸的间距；说明挪进沿上时置 0 |

单位分两种，取决于这张卡纸的高是怎么来的：

- **列表三面**（相册格 / 封面 / 套册格）高由宽推出来，边宽写 `cqw`（卡纸宽的 1%），横竖同尺。
  `cqw` 由外层 `.film-tile` / `.trip-cover-slot` / `.stamp-slot` 上的 `container-type: inline-size` 提供——
  栅格自己不能当自己的容器，所以这层外壳不能省。
- **开包舞台**的照片垫高是舞台给的（上下 inset 定死），边宽写百分比；`below` / `foot` 因此落在垫子里面，
  不像列表三面落在卡纸之外。

### 各面的零件与默认区域

### 界面面的常驻零件

卡纸之外还有一批不属于任何一张卡纸的零件，同样是**一次渲全、默认 `display: none`**，
皮肤在自己的 `[data-theme]` 下打开。日光一个都没开，所以拿得到逐像素 0 差异。

| 零件 | class | 用在哪 | 说明 |
|------|-------|--------|------|
| 设置行图标 | `.me-row-icon` | `.me-row` 内首位 | [`MeRowIcon`](../../apps/web/src/components/MeRowIcon.tsx)，一枚淡彩底 + 线性图标 |
| 首字母牌 | `.me-avatar` | 「我的」名片 | 昵称首字母，皮肤决定是圆牌还是方牌 |
| 淡彩进度条 | `.tint-bar` | 识图配额、套册点亮进度 | 比例由页面挂 `--bar-ratio`（0–1），CSS 算不出 used / limit |
| 已收录种脸 | `.collection-faces` | 图鉴首页已收录行 | 最多四张种的照片。取法见 `pickCollectionFaces`：每界稀有度最高的一种，不满再按稀有度补 |
| 收集树门 | `.collection-tree-door` | 图鉴首页收集树行 | 淡色整棵树。`src` 只在声明了 `collection` 域的皮肤上才有 |

`.me-row` 是「我的」与「图鉴」共用的一行菜单，加图标就是往里塞一枚 `<MeRowIcon>`，
新图标在 `MeRowIconName` 里登记名字并指定用第几号淡彩。`.tint-bar` 同理共用：
两处都是「已经用掉／已经集到多少」，别各写一份，要换色就在皮肤里追加一条更具体的选择器
（清透的 `.volume-tile-bar` 就是这么改成苔绿的，好和那行图标同色）。

### 改法示例

把封面的日期挪到卡纸下沿去打字：

```css
[data-theme="<id>"] .trip-cover-slot {
  --mount-lip-bottom: 11cqw;
}
[data-theme="<id>"] .trip-cover-mark {
  grid-area: lip-bottom;
  place-self: center start;
  margin: 0 0 0 3cqw;
}
```

### 实例：清透的相册格与封面

清透和日光在这两个面上的真区别就是这一层——**日光把说明写在框外**（像图鉴条目），
**清透写在卡纸下沿**（像实物上的字）。零件是同一套，只是启用的区域不同：

```css
[data-theme="clear"] .film-tile {
  --mount-lip-bottom: 13.3cqw; /* 三边 5.5cqw，下沿宽出来放那行字 */
}
[data-theme="clear"] .film-tile-mark {
  display: flex; /* 日光把这道边关着 */
  font-size: 5.1cqw;
  color: var(--mount-ink);
}
```

旅途封面把**两个**零件搬上了同一格下沿：标题靠左、「几张 · 日期 · 地点」靠右。
同一个 `grid-area` 里放两件东西全靠 `justify-self` 分头，两边的 `max-width` 加起来正好 100%，
所以长标题配长标注也不会叠在一起：

```css
[data-theme="clear"] .trip-cover-title {
  grid-area: lip-bottom;
  justify-self: start;
  max-width: 38%;
}
[data-theme="clear"] .trip-cover-mark {
  grid-area: lip-bottom;
  justify-self: end;
  max-width: 62%;
}
```

另外，同一种物件在不同尺寸上**不该用同一个百分比**：相册格两列、卡纸窄，
5.5cqw 的边正好；旅途封面宽一倍多，同样 5.5cqw 就显得笨重，收到 3cqw 才和示意对得上。

`.film-tile-mark`（日期＋片号）本来就一直渲染着、默认 `display: none`，
皮肤要用自己打开就行，不必改组件。

> 反面教材：这道边第一版没打开，转而**在 `film-frame.svg` 里画了三条灰色小方块假装是字**。
> 远看像那么回事，凑近就是三根杠——皮肤看着「生效了」，示意里那个东西其实一个都没落地。
> 零件已经在 DOM 里了就别在图里仿它。

### 五个坑

- **沿上的字别写 `line-height: 1`**。卡纸沿窄，第一反应是把行高压到 1 好塞得下，但 1em 的行盒装不下
  中日文字形（它们本来就顶满 em 框、常常还溢出一点），配上为省略号而加的 `overflow: hidden`，
  字的顶端就被削掉五分之一。压不下就调字号或调沿宽，行高留 1.3 以上。
  封面的「9 张照片 · …」和开包卡纸上的地点都栽过这一下。
- **线名不能连着写两个方括号**。`… 8cqw [mount-end] [below-start] auto` 会让整条 `grid-template-rows` 作废、
  静默回退到自动排版；必须合并成 `[mount-end below-start]`。
- **`align-content: start` 不能删**。同排格子被拉到一样高时，多出来的高度会摊给 `auto` 行，
  卡纸就比窗口高出一截、边框 SVG 被拉变形。改造前的老写法正是栽在这里：430 宽下右列的边框实测 215.77×215.77，
  比格子本身还宽 22.8px，一直在往外溢。
- **`cqw` 有 1/64px 的舍入**。封面共享角标从 `right: 8%` 换算成 `cqw` 后横向差了约 0.3px，肉眼不可见但逐像素比得出来。
  要求严丝合缝的位置别用 `cqw` 表达。
- **删除按钮进不了卡纸**。它是独立 `<button>`，不能嵌在片框那个 `<button>` 里，只能待在 `.film-tile` 外层。
  皮肤要把它挪上卡纸，得先把点击结构改掉。

## 2.4 槽位层：整块换实现

摆放层换不了两样东西：**这一下怎么动**，和**某个概念用什么表现**。
它们不是位置问题——「翻书」换成「拧开舷窗」不是把封面挪个位置就成的。
这类交给皮肤直接给实现，登记在 [`themes/slots.ts`](../../apps/web/src/themes/slots.ts)。

回退和 §2.1 的资源域一个写法：皮肤没登记的槽位落回 `DEFAULT_SLOTS`（日光那套物件），
所以新皮肤可以一个槽位都不写。`DEFAULT_SLOTS` 是全量类型，少写一个编译就不过——兜底那条路永远是全的。
用户默认是清透，但它覆盖的槽位只登记在 `THEME_SLOTS.clear`，不会拿去给没登记的皮肤兜底。

**边界没变**：槽位决定「怎么演、长什么样」，阶段何时推进、数据从哪来仍归骨架。
用户点了按钮把 `sealed` 推到 `revealing` 是骨架的事；`revealing` 演多久、演完什么样，是皮肤的事。

### 槽位清单

| 槽位 | 种类 | 换掉的是 | 状态 |
| --- | --- | --- | --- |
| `raritySeal` | 组件 | 稀有度用什么表现（默认是齿边封蜡章） | 已接 · 清透已覆盖 |
| `settleStage` | 组件 | 开包舞台：DOM 与揭示的整套调度 | 已接 · 清透已覆盖 |
| `lift` | 动作 | 照片在格子与大图之间搬运 | 已接 · 只有默认实现 |
| `slot` | 动作 | 收下之后照片落进相册格子 | 已接 · 只有默认实现 |
| `album` | 动作 | 进出旅途相册（默认是翻书） | 已接 · 只有默认实现 |

**不要把没接的槽位写进 `ThemeSlots`**——声明了却没人调用，
和在 `THEME_META.assets` 里声明不存在的资源域一样是空头支票。

### 实例：清透换掉了开包舞台与稀有度

这几块换的是**物件本身**，不是颜色，所以没法靠 token 或摆放解决：

- 日光的开包是「拆封」——牛皮纸包、封蜡、壳被抬走。
- 清透的开包是「显出来」——照片带着暖白边从一小叠里浮上来、由糊到清。
  没有可撕的东西，也**不许压暗**：这套底是亮的，一压暗就回到暗房去了。

于是 [`ClearRevealStage`](../../apps/web/src/components/ClearRevealStage.tsx) 整只替掉
`SettlePackStage`，[`ClearRankChip`](../../apps/web/src/components/ClearRankChip.tsx)
（淡彩药丸，走各档的 `--rarity-*-bg/-fg`）替掉封蜡章。开包舞台与稀有度药丸共用一个 CSS 文件，
和 `SettleRaritySeal.css` 同一个道理：某套皮肤的物件不进共享结构表。

物种树已改成整页 3D 场景（`SpeciesTree3D`），不是「图鉴里一层的排版」，原先的 `collectionTreeLayer` 槽位已删。图鉴首页那扇收集树门仍是结构零件（`.collection-tree-door`），跟槽位无关。

节奏也归皮肤——默认舞台 700ms（撕开是「一下」），清透 780ms（显清楚是「一段」）。

`SettleStageProps.mark`（`{ when, where }`）是给**卡纸型**皮肤打在片框上的时间与地点。
命名到语义为止：叫 `when` / `where` 不叫 `left` / `right`，摆左摆右、用不用得上是皮肤的事，
默认那只牛皮纸包上没地方写字，收到也不理会。

### 用法

```tsx
// 渲染时现取，和资源 helper 同一套路数
const SettleStage = themeSlot("settleStage");
return <SettleStage phase={phase} photoUrl={url} rarity={rarity} onRevealed={onRevealed} />;
```

皮肤要覆盖就在 `THEME_SLOTS` 里登记。表里存的是**取实现的函数**而不是实现本身：
默认实现之间会互相引用（开包舞台里要取稀有度槽位），写成惰性的才不怕模块加载顺序。

```ts
const THEME_SLOTS: Partial<Record<ThemeId, SlotTable>> = {
  clear: { settleStage: () => ClearRevealStage },
};
```

### 阶段归谁推：以开包为例

```
页面：用户点「请过目」        → setPhase("revealing")
舞台：自己演 REVEAL_MS 这么久 → onRevealed()
页面：                        → setPhase("open")
```

时长写在舞台组件里（默认 700ms），同时挂成 `--reveal-ms` 供 CSS 用——
壳抬起的动画和「多久之后转 open」必须同源，否则壳还在抬、照片已经展出了。
皮肤换舞台就一起换了节奏，页面不需要知道。

### 动作槽位怎么分工

骨架负责所有**与皮肤无关的杂务**，皮肤只拿到演员和起止位置：

- 骨架做：建飞行体、按起点摆好、藏源格子、减动偏好下直接跳到终点、取消检查、收尾清理
- 皮肤做：从起点到终点这段时间里怎么走——时长、缓动、路径、中途还带谁一起动

`LiftBeat.duration` 是骨架给的**建议**时长：这一下在流程里有多重（进详情 vs 退回列表）是骨架知道的，
皮肤可以不听。

两个骨架的入口分别是 [`photoLift.ts`](../../apps/web/src/photoLift.ts) 的 `playPhotoLift`
和 [`photoSlot.ts`](../../apps/web/src/photoSlot.ts) 的 `playPhotoSlot`，
缺省实现（`flyEaseOut` / `slideUpFromPocket`）就在同一个文件里。八个搬照片的调用点全走 `playPhotoLift`，
所以接槽位没动任何一个调用点。

`AlbumBeat` 的演员比别的多（封面克隆、内页、垫纸，还有身后那页旅途列表）。
默认的翻书会把身后那页糊到 44px 并放大 1.14 倍——换动作时这只手也归皮肤，所以 `shelf` 一起交出去。
它是唯一一个**双向**的动作槽位，`dir` 分进出；两个方向都归同一个实现，
不然换皮肤时会出现「翻着进去、淡出出来」这种半套东西。

进出相册这块拆得比另外两个深，因为原来动作和图层管理搅在一起。现在：

- [`components/TripBookLayer.tsx`](../../apps/web/src/components/TripBookLayer.tsx) 只管图层：
  把层钉到 `main.content` 的框上、`opening / open / closing` 相位机、消费列表页交接的起始位置、
  演完之后 `navigate("/")`、以及**没有封面克隆体时的退化路径**（直接从别处进相册，没得可演）
- [`bookFlip.ts`](../../apps/web/src/bookFlip.ts) 只管编排：拿起、挪到中间、翻开，四段共 1280ms

骨架量出来的 `from` / `held` 是**层内坐标**，皮肤直接 `applyBox` 就行，不用再换算。
这儿的测量故意不走 `motion.ts` 的 `measureBox`——那个会对齐设备像素，对齐了封面起飞时会跳一下。

### 两个坑

- **`themes/index.ts` 不要再导出 `slots.ts`**。它 import 了组件，而组件 import 那个桶文件，
  一转出去就成环。用的人直接 `from "../themes/slots"`。
- **切皮肤要整棵树重渲才生效**。槽位和资源 helper 一样在渲染时现取，不是响应式的。
  现在切皮肤走「我的 → 外观」再返回，天然会重渲；将来做即时预览得另加订阅。

## 3. 如何新增皮肤（清单）

1. 新建 `apps/web/src/themes/<id>.css`，选择器 `[data-theme="<id>"] { … }`，填满 §2 变量。  
2. 备资源包 `public/<域>/<id>/`（文件名对齐 daylight）。只出一部分也行——见 §2.1 回退。  
3. `themes/core.ts`：把 `"<id>"` 加入 `ThemeId` 与 `THEME_IDS`，并在 `THEME_META` 登记 `scheme` / `assets` / `voice`。API [`theme-id.ts`](../../apps/api/src/theme-id.ts) 的允许列表一并加上，否则外观写入账号会 400。  
4. `main.tsx`：`import "./themes/<id>.css"`。  
5. `packages/messages`：加 `theme.<id>` 与 `theme.<id>Hint`（外观页读这两个 key）。要换包装用词再按 §5 加 voice。  
6. 若该皮肤要专用 Web 字体：改 `index.html` 的 fonts link（或多皮肤时按需加载，避免无关字体）。  
7. 结构不同就按 §2.3 在 `[data-theme="<id>"]` 下改摆放；整块要换实现（动作、稀有度表现）按 §2.4 登记槽位。两样都不做也能出一套能用的皮肤。  
8. 用户在「我的 → 外观」切换（`applyTheme` + 写入账号）；**不要**为换皮复制页面组件。  
9. 验收：默认 `clear` 仍正常；切到 `daylight` 后按钮/导航/稀有度徽章/地图点/弹层均有色且无大片未定义回退；深色皮肤额外查照片垫、地图简图与弹层遮罩。

## 4. 明确不做

- 不为换皮分叉 `pages/*` 业务逻辑或复制整页；结构差异走 §2.3 的摆放层，整块换实现走 §2.4 的槽位层。  
- 皮肤不碰数据、状态机、请求、路由、埋点——只拿算好的值决定怎么摆、怎么演。账号皮肤是用户资料，走 `themeAccount.ts` / `PATCH /api/auth/me`，不进 `themes/*.css`。  
- 不把长中文或品牌色写进 API 路由。  
- 不在未登记皮肤 id 时写入本机缓存或账号（`isThemeId` / `canonicalizeUserTheme` 会拒掉）。  
- 不在 `THEME_META.assets` 里声明没有实际文件的域。

## 5. 包装用词（voice）

同一个功能，不同皮肤可以有不同说法：一套说「专家鉴定中」，另一套可以说「显影中」。
这层落在 `packages/messages/src/voices/`，一个皮肤一张，
类型是 `Partial<Record<MessageKey, string>>`——只写与基础文案不同的 key，其余自动落回 `zh.ts`。
**当前两套皮肤都用 `default`，`voices/` 里一张表都没有。** 曾有过 `voices/lightbox.ts`（把「相册 / 翻开第一页 / 套册」
改成「一卷 / 装上第一卷 / 片夹」，10 个 key），随灯箱设定一并删除——清透换的是观感不是说法，
`VoiceId` 于是收回到只剩 `"default"`。机制留着：将来真有一套自带叙事的皮肤（比如深海）再加回来，
那时 `VoiceId` 要重新变成联合类型。

- `applyTheme` 会调 `setMessageVoice(THEME_META[id].voice)`，切皮肤即换词
- 覆盖表里的 key 必须已存在于 `zh.ts`，否则类型不过
- 服务端从不调 `setMessageVoice`，API 恒用基础文案
- 当前只有 zh；加语言时按语言分表
- **只换说法，不换含义**：状态码、功能、流程一律不动（见 [`品牌叙事.md`](./品牌叙事.md) §2）

## 6. 加功能时怎么补皮肤

**新功能默认是不带皮肤的**，得有人主动补。这一节是那份清单。
判断顺序从上往下，命中哪条做哪条；一条都不命中就在 PR 里说明为什么不用管。

1. **写了用户看得见的中文句子？** → 落 `packages/messages`，走 `t()`。
   句子里带了皮肤专属的说法（相册 / 片夹 / 舷窗）就同时想清楚别的皮肤怎么说，按 §5 加 voice 覆盖。
2. **写了颜色、圆角、阴影、字体？** → 一律 `var(--*)`。§2 里没有合适的语义 token 就新开一个，
   **同轮把所有皮肤的 `themes/*.css` 都填上**。漏填的皮肤会拿到 `unset`，不是回退。
3. **加了承载质感的结构件（片框、封面、格子、舞台这类）？** → 按 §2.3 把零件一次渲全，
   位置交给 `grid-area`。不要用条件渲染决定某个零件在不在——那样皮肤就没法把它挪到别处。
4. **加了新的图片资源？** → 放 `public/<域>/<themeId>/`，经 `themes/*Assets` helper 引用。
   只出资源兜底那一份（日光）就行，别的皮肤按 §2.1 自动回退。**不要**在页面里写死 `/volumes/daylight/…`。
5. **加了动画，或者加了一个「概念的表现方式」（新的等级、新的仪式、新的状态章）？**
   → 这是最容易漏的一条。按 §2.4 判断：别的皮肤有没有可能想换掉这一整块？
   有，就开个槽位（接口进 `slots.ts`，默认实现登记进 `DEFAULT_SLOTS`）；
   没有，就在 PR 里写一句为什么这块对所有皮肤都一样。**默默写死是不允许的。**
6. **改完对着默认皮肤逐像素验一遍**。方法见 [`scripts/walkthrough/README.md`](../../scripts/walkthrough/README.md)。
   纯改造类改动（只搬结构、不动观感）的验收标准是 **0 差异**，"看起来一样"不算。

漏补的代价不是当场报错，是**下一套皮肤做到一半才发现有块地方换不了**，那时候改要动的面大得多。

## 7. 后置

- 槽位层五个槽位已全部接上。清透覆盖了 `raritySeal` 与 `settleStage`，**查表这条路已经走通**；
  三个动作槽位（`lift` / `slot` / `album`）仍只有默认实现，覆盖路径没走过。
  第一套真去覆盖动作的皮肤多半会撞出接口没想周全的地方，那时候改 `slots.ts` 的类型是正常的。  
- **动作换掉之后没有自动验收手段**。改造类改动的逐像素比对只管得住静止画面，
  动作的中间帧抓不到：无头浏览器的虚拟时钟要么在等图片解码时不走（拍出白帧），
  要么把 rAF 一口气跑完（拍到的已经是终态）。`lift` 和 `album` 两次都栽在这上面。
  走查页能预置交接不必点鼠标（`?lift=<obsId>&trip=<tripId>`、`?book=<tripId>`），
  但落在哪一帧卡不住。**碰动作只能人工过一遍**，别在这上面耗时间。  
- **稀有度后四档的色不跟皮肤走，这是有意的**。N / R / SR 的封印读 `--rarity-*-seal`，
  SSR / UR / LR / XR 的金属渐变、辉光、字牌是这枚蜡章自己的材质，写在
  [`SettleRaritySeal.css`](../../apps/web/src/components/SettleRaritySeal.css) 与同名 tsx 里。
  没做成 token，是因为换一套皮肤要的多半不是「换个金色的蜡章」而是另一个物件；
  真要换就走 `raritySeal` 槽位整枚换掉。共享的 `styles.css` 里已不再有这些品牌色。  
- `public/onboard/` 不是主题化资源域：登录后的三页插页仍是日光那套铜版画，在清透皮肤下与四周不搭。要么把它并入 `trips` 域，要么单开一个 `onboard` 域。
  引导态底栏那三条 `::after` 下划线同理没跟着换（清透把常态那道换成了淡彩药丸），
  因为那几条选择器权重比皮肤层高，得连 `.app-shell.is-onboard[data-onboard-tab=…]` 一起写才压得住。  
- 地图页刻意不主题化：在线瓦片来自天地图，换不了配色；只有离线兜底样式 `simpleStyle()` 认 `scheme`，

  （那要让结算页多发一次请求，是数据不是皮肤），也不该假造别人拍了什么。
