# 文案分区（固定区 / 可文案区）

> 机制来源：2026-09-04 拍板。界面功能文案分两类，中间隔着机器闸门，不是靠理解区分。

## 为什么要分

皮肤 voice（叙事说法）能覆盖界面文案，但不是所有文案都该被包装：
「N · 常见」改成「小清透」会让稀有度跨页面对不上；「确认语」是防误删闸门，
安全机制不吃包装。所以文案分两区，**固定区永远不被 voice 换说法**。

## 判定准则（三问，任一命中即固定区）

1. **换了说法，功能指代会模糊吗**——稀有度档位、状态名、阶元词、排序标签这类概念锚点
2. **它是事实/合规/数据的表述吗**——法规定义、科学阶元、审图号、错误码译文、套册内容
3. **它在安全或后果说明路径上吗**——删除确认语、解散后果、危险操作提示

三问都不中、纯场景与情绪包装的，归可文案区。另：`admin.*` 全区固定。

## 四道闸门（机器强制）

| 闸 | 位置 | 拦什么 |
|----|------|--------|
| 结构闸 | `zh.ts` 拆 `zhCore` / `zhFlavor` 两个对象 | 新增文案被迫二选一，放错区一眼可见 |
| 类型闸 | `ThemedMessageKey = keyof typeof zhFlavor`；voice 表类型 `Partial<Record<ThemedMessageKey, string>>` | 覆盖固定 key 直接编译报错 |
| 运行时闸 | `t()` 内 `themedKeys.has(key)` 判定 | 动态拼 key、js 侧绕过 |
| 校验闸 | `scripts/check-voice.py` | 覆盖表 ⊆ 可文案区；成套组完整；运行时闸在位 |

## 成套覆盖组（要换全换）

- **nav 四词**：`nav.trips` / `nav.map` / `nav.collection` / `nav.me`
- **点亮词族**：`collection.volumeStampEmpty` / `collection.volumeDone` / `settle.volumeCompleted` / `settle.volumeCompletedMore` / `settle.volumeSlotLit` / `settle.volumeSlotLitMore`

## 加新文案时怎么走

1. 按三问判定归属区
2. key 加进 `zhCore` 或 `zhFlavor` 对应位置（**不要**只加进合并后的 zh——两区物理分开）
3. 若归可文案区且属成套组，整组一起考虑
4. 跑 `python scripts/check-voice.py` 自检
