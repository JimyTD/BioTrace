# 文案语感基准（voice 规格书）

> 来源：2026-09-07 文案总策划方案拍板。这是给**人**评审用的尺子；
> 机器下限在 scripts/check-voice.py（语感 lint 挂 `pnpm check:copy`）。
> 分区机制（固定区/可文案区）见 docs/features/文案分区.md。

## 为什么需要基准

voice 机制让皮肤能换说法，但"换说法"没有尺子就会失控：灯箱 voice 当年
把「相册」改「一卷」，同一界面里册族与卷族混搭出缝。基准管两件事：

1. **基底文案**（zhFlavor 43 key）自己要先合格——今天所有用户读到的就是它
2. **未来任何 voice 覆盖表**写出来，人工评审时有对照规格

## 一、人称与称谓

- 对用户一律「你」，**禁用「您」**（平视，不端着）
- 对生命一律「**它**」（detail.reidentifyPlaceholder 原用「他」已改）
- 不出现真名叙事之外的昵称化（不出现"小家伙""这位"这类娇宠腔）

## 二、句式

- **黄金句式**：现状句 + 行动句。trips.empty「还没有旅途。写下名字，翻开第一页。」是样板
- 界面句 = 两个短句上限；单句静态字（剥占位符后）**≤ 14 字**，超了拆句或移固定区
- 仪式句（开包、成册播报）允许 `·` 分隔符节奏，不按散文句法审
- 句号收尾，**禁感叹号**；toast 可无标点
- 疑问句只在真提问时用（表单校验、确认弹层），不用反问做语气装饰

## 三、五大隐喻家族（白名单）

同一手势全 app 只有一个家族的说法，家族内成套（check-voice.py GROUPS 强制
覆盖表整族齐换）。跨家族混搭出缝是灯箱时代的教训，禁止。

| 家族 | 说法 | 边界 |
|------|------|------|
| **册族** | 翻开、册页、整册、第一页 | 相册与旅途的容器心智。上限是"册"，不伸到"书/卷/档案" |
| **证书族** | 鉴定证书、请过目、收下 | 权威命名的心智锚点。「证书」vs「定名样片」悬案已拍板：保留证书 |
| **点亮族** | 点亮、一格、整册点亮 | 认出→点亮的因果链。量词统一「格」 |
| **落点族** | 落点、足迹、点 | 地图心智。不上"坐标/标记"这类工具词 |
| **专家族**（基底签名） | 专家鉴定中、专家只敢认到大类、专家歇了 | **固定区，永不被 voice 覆盖**。是 BioTrace 的人格签名，所有皮肤共用同一个"专家"。第三区（人格区）设计见 §五 |

**登记进 GROUPS 的家族**：nav 四词、点亮词族（含 onboard.collectionLede）、
册族、证书族、落点族。专家族在固定区，无需成套保护——它没有覆盖面。

## 四、术语口径

- 树上的收录物统一「**收录**」：tree3d.statGot「已收录 {count} 项」、
  viewCollection「查看收录」、sheetSum「这一支下有 {count} 项收录」。
  nav 仍叫「图鉴」——那是页面名；树上叫收录——那是动作与状态。
- 量词：点亮族用「格」，册族用「本」，树上条目用「项」
- 「项」vs「种」：树上节点不全是种（科、目也计数），保留「项」不冒充「种」

## 五、第三区（人格区）设计——未实施

error.identifyQuota 这类"专家家族"文案，未来若允许皮肤换说法，方案是：
开 ThemedMessageKey 之外的第三类型 PersonaKey，voice 表按 key 校验**必含锚词**
（如 quota 类必含「今日」+「用尽」语义锚）——换说法可以，换含义与事实不行。
**触发条件写死：第一套叙事皮肤立项时启用。不为零张 voice 表预建机器。**

## 六、lint 边界（机器管什么）

check-voice.py 语感 lint 只拦：感叹号、「您」、静态字超 14、
家族组 key 存在性、voice 占位符保全。**文采、节奏、意境一律人评**，
评审 checklist 走 walkthrough 走查页（scripts/walkthrough/）。
