## 0. 项目是什么（部署前必读）

| 项 | 内容 |
|----|------|
| 产品 | 个人向「旅行自然观察」Web：旅途 → 上传照片 → 云识图 → 抽卡开包 → 图鉴/地图 |
| 仓库 | pnpm monorepo：`apps/api`（Hono+SQLite+识图）、`apps/web`（Vite+React+MapLibre）、`packages/messages` |
| 登录 | **邮箱+密码**；Resend 用于找回；生产 **`DEV_AUTH=0`**。本机调试可临时 `DEV_AUTH=1` |
| 识图 | 默认 Gemini；短限流等待 / 日额尽切智谱 GLM。国内机访问 Gemini 需 **HTTPS_PROXY（新加坡代理）** |
| 地图 | 浏览器**直连** OpenFreeMap + MapLibre，**不要**在服务器反代瓦片 |
| 数据 | SQLite + 本地展示图目录；**不上** COS/云数据库（本 Cut） |
| 不做（部署 Cut） | 旅途元数据 UI、稀有度封顶表（见 06 §3.6）、COS；Android 见独立 Cut 6 / [`docs/09`](./09-Android套壳.md) |

### 目标架构

```text
Browser ──HTTPS──► Nginx（宿主机，Let’s Encrypt）
                      ├── 静态 /var/www/biotrace  ← apps/web/dist
                      └── /api/* ──► 127.0.0.1:8787  ← Docker biotrace-api
                                         volume: ./data → /data
                                           ├── biotrace.db
                                           └── uploads/
API ──HTTPS_PROXY──► 新加坡代理 ──► Gemini
API ──常直连──► 智谱 GLM（国内）
Browser ──直连──► OpenFreeMap 瓦片
```

### 机器规格（已拍板）

- 腾讯云轻量应用服务器，**专用**（不与其他业务混部为佳）
- **2 核 / 2G RAM / 40G 系统盘**
- **Ubuntu 22.04 或 24.04 LTS（x86_64）**
- 防火墙放行：**22、80、443**
- 2G 内存：部署后执行仓库内 `deploy/setup-swap.sh`（2G swap）
- **不需要 GPU**

### 部署前需向用户确认的秘密（勿写入 git）

1. 域名（已 A 到该机公网 IP）  
2. SSH 登录方式  
3. `GEMINI_API_KEY`、`ZHIPU_API_KEY`  
4. 新加坡代理完整 URL（`HTTPS_PROXY`）  
5. 长随机 `SESSION_SECRET`  
6. `RESEND_API_KEY`、已验证发件地址 `MAIL_FROM`

## 1. 仓库内已有制品（勿重复造轮子）

| 路径 | 用途 |
|------|------|
| [`Dockerfile`](../Dockerfile) | 仅构建 API（含 workspace 依赖 `@biotrace/messages`），Node 22 |
| [`docker-compose.yml`](../docker-compose.yml) | 服务名 `api`；`env_file: deploy/.env.production`；端口 **仅** `127.0.0.1:8787:8787`；卷 `./data:/data` |
| [`deploy/.env.production.example`](../deploy/.env.production.example) | 复制为 `deploy/.env.production`（gitignore） |
| [`deploy/nginx.biotrace.conf.example`](../deploy/nginx.biotrace.conf.example) | 宿主机 Nginx：静态 + `/api` 反代 + TLS 占位 |
| [`deploy/setup-swap.sh`](../deploy/setup-swap.sh) | 可选 2G swap |
| 根 `packageManager` | `pnpm@11.20.0`（构建前端时用 corepack） |

**约定：**

- API **不要**对公网直接暴露 8787；只给本机 Nginx。  
- Web **不是** Docker 服务：在宿主机（或 CI）`pnpm --filter @biotrace/web build`，产物同步到 `/var/www/biotrace`。  
- 前端请求路径为相对路径 `/api/...`（与站点同域）；故 Nginx 必须同源反代 `/api`。  
- `APP_ORIGIN` 与 `CORS_ORIGIN` 均为 `https://你的域名`（无尾斜杠）；魔法链接依赖 `APP_ORIGIN`。  
- `COOKIE_SECURE=1`；生产 `DEV_AUTH=0`。  
- 容器内：`DATABASE_URL=file:/data/biotrace.db`，`UPLOAD_DIR=/data/uploads`（compose 已写死 environment，勿改成相对路径）。

## 2. 上机步骤（顺序）

### 2.1 系统

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y git nginx certbot python3-certbot-nginx ca-certificates curl rsync
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"   # 重新登录后再 docker
```

### 2.2 代码与配置

```bash
sudo mkdir -p /opt/biotrace /var/www/biotrace /var/www/certbot
sudo chown "$USER:$USER" /opt/biotrace
cd /opt/biotrace
# git clone <repo> .   或 rsync 上传整个仓库（含 pnpm-lock.yaml）

cp deploy/.env.production.example deploy/.env.production
# 编辑：SESSION_SECRET、APP_ORIGIN、CORS_ORIGIN、COOKIE_SECURE=1、DEV_AUTH=0、
# RESEND_API_KEY、MAIL_FROM、GEMINI_*、ZHIPU_*、HTTPS_PROXY

mkdir -p data/uploads
sudo bash deploy/setup-swap.sh    # 建议
```

### 2.3 API 容器

```bash
cd /opt/biotrace
docker compose build
docker compose up -d
curl -sS http://127.0.0.1:8787/api/health
# 期望 JSON：ok=true；查看 geminiConfigured / zhipuConfigured
docker compose logs --tail=80
```

### 2.4 前端静态（需 Node 22 + pnpm）

```bash
# 若 apt 的 node 过旧，用 NodeSource / fnm 安装 Node 22，然后：
sudo corepack enable
cd /opt/biotrace
pnpm install
pnpm --filter @biotrace/web build
sudo rsync -a --delete apps/web/dist/ /var/www/biotrace/
```

也可用本机 Windows 构建后把 `apps/web/dist/` rsync 到服务器 `/var/www/biotrace/`。

### 2.5 Nginx + 证书

1. 复制 `deploy/nginx.biotrace.conf.example` → `/etc/nginx/sites-available/biotrace`  
2. 全局替换 `biotrace.example.com` 为真实域名  
3. `sites-enabled` 启用；去掉 default；`nginx -t && systemctl reload nginx`  
4. 域名已解析后：`sudo certbot --nginx -d 你的域名`  
5. 确认 `APP_ORIGIN`/`CORS_ORIGIN=https://你的域名`，然后 `docker compose up -d --force-recreate`

**证书未就绪时的烟雾：** HTTP 下若 `COOKIE_SECURE=1` 会话会失败——测 HTTP 时临时 `COOKIE_SECURE=0`，上 HTTPS 后改回 `1`。

## 4. 日常运维

```bash
# 备份数据
tar czf biotrace-data-$(date +%F).tgz -C /opt/biotrace data

# 更新
cd /opt/biotrace && git pull
docker compose build && docker compose up -d
pnpm install && pnpm --filter @biotrace/web build
sudo rsync -a --delete apps/web/dist/ /var/www/biotrace/
```

日志：`docker compose logs -f --tail=200`  
识图提供商：日志中 `[identify] ok provider=gemini|zhipu`。

## 5. 常见坑

| 现象 | 排查 |
|------|------|
| 登录后立刻掉会话 | `COOKIE_SECURE=1` 但站点仍是 HTTP；或 `APP_ORIGIN`/`CORS_ORIGIN` 与地址栏不一致 |
| 收不到邮件 | Resend 域名未验证；`MAIL_FROM` 不对；查 API 日志 Resend 错误 |
| 点链接无效 | `APP_ORIGIN` 指错；token 过期/已用；Nginx 未反代 `/api/auth/verify` |
| 前端 404 /api | Nginx 未反代 `/api/`；或 API 容器未在 127.0.0.1:8787 监听 |
| Gemini 全失败 | `HTTPS_PROXY` 不可达；看 API 日志；应自动试 GLM |
| 构建 API 镜像失败 | 需完整 `pnpm-lock.yaml`；网络装依赖；`pnpm-workspace.yaml` 含 `allowBuilds: sharp` |
| 磁盘满 | 展示图在 `data/uploads`；定期备份并清理 |
