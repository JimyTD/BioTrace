# BioTrace 服务器运维接入

本手册建立两条独立通道：SSH 是日常部署主通道；腾讯云 TAT MCP 与网页 OrcaTerm 是引导和救援通道。两条通道必须都保留，不能互相依赖。

## 一次性接入

1. 本机运行下列命令，生成独立的 `biotrace_deploy` ED25519 私钥、安装 SSH MCP 共享产物，并打印公钥安装命令：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup_biotrace_ops_machine.ps1 -Target none
   ```

2. 通过腾讯云 Lighthouse 的 OrcaTerm 网页终端，或现有 `tencent-lighthouse` TAT MCP，以 root 身份执行脚本打印的**一整条** `authorized_keys` 命令。

3. 验证原生 SSH 后才允许继续：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup_biotrace_ops_machine.ps1 -Target none -Verify
   ```

4. SSH 已验证后，使用 SSH 主通道执行以下命令关闭密码认证。必须先校验，再 reload；保留 TAT/OrcaTerm 作为救援通道。

   ```bash
   install -d -m 755 /etc/ssh/sshd_config.d
   cat >/etc/ssh/sshd_config.d/10-biotrace-key-only.conf <<'EOF'
   PasswordAuthentication no
   PermitRootLogin prohibit-password
   PubkeyAuthentication yes
   EOF
   sshd -t && systemctl reload ssh
   sshd -T | grep -iE 'passwordauthentication|permitrootlogin|pubkeyauthentication'
   ```

正常情况下可通过 SSH 回滚：`rm /etc/ssh/sshd_config.d/10-biotrace-key-only.conf && systemctl reload ssh`。只有 SSH 不可用时，才通过 TAT/OrcaTerm 执行同一条命令。

## 可选 MCP 注册

SSH MCP 只是原生 SSH 的便利层，不能替代 `ssh -i ~/.ssh/biotrace_deploy`。

- Cursor：把首次命令的 `-Target` 改为 `cursor`，脚本会合并写入 `~/.cursor/mcp.json`。
- Codex：使用 `-Target codex` 打印 TOML 片段，添加到 `~/.codex/config.toml` 后新开会话。
- 任何客户端：共享配置位于 `~/.ssh-mcp/config.json`，连接名为 `biotrace`；其中的黑名单强制禁止 `git reset --hard`、`git clean`、删除数据卷和停止整套 Compose。

## 日常部署

推送到 GitHub 后，通过 SSH 启动仓库内的部署器：

```bash
nohup /opt/biotrace/scripts/ops/deploy-server.sh >/dev/null 2>&1 &
```

它会取得 `/var/lock/biotrace-deploy.lock`，检查 tracked 工作树漂移，经 Xray 执行 `git pull --ff-only`，再按改动路径构建 API/Web 并完成验收。需要强制完整构建时传 `--all`。

轮询时使用有限输出，禁止 `tail -f`：

```bash
cat /var/lib/biotrace/deploy.status
tail -n 80 "$(sed -n 's/^log_file=//p' /var/lib/biotrace/deploy.status)"
```

部署器必须返回 `result=success`。它会验证 `/api/health`、容器到宿主代理的解析、实际 Xray 出口 IP、`index.html` 的 `no-store` 缓存策略及不存在静态资源的 404。若改动包含 `apps/mobile/`，日志会标记需按 [`OPS.md`](./OPS.md) §7.2 发布 APK；服务器不保存签名密钥，也不构建 APK。

## 服务器本地运维配置

首次部署前，以 root 身份创建未入库的出口期望值。值必须是 SG1 当前出口 IP；部署器将严格比对，任何其他出口都会失败。

```bash
install -d -m 700 /etc/biotrace
cat >/etc/biotrace/ops.env <<'EOF'
BIOTRACE_PROXY_EGRESS_IP=<SG1 current egress IP>
EOF
chmod 600 /etc/biotrace/ops.env
install -m 644 /opt/biotrace/deploy/logrotate.biotrace.conf.example /etc/logrotate.d/biotrace
logrotate -d /etc/logrotate.d/biotrace
```

SG1 更换出口 IP 时，先更新 `/etc/biotrace/ops.env`，再运行部署器。该文件和 `/etc/logrotate.d/biotrace` 都是服务器运行配置：模板在 git，实际值不入库。

## 本机 Web 环境变量

如生产 Web 构建需要 `VITE_*` 值，在服务器本地创建 `deploy/.env.web.production`，只放浏览器构建所需的 `VITE_*` 键。此文件已 gitignore，不可放 API 密钥。部署器发现该文件时才把它传给 Web 构建容器。
