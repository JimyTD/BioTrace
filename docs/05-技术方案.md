## 块 A：系统形态（已结案）

### A.1 总览

```text
[Web App] ──┐
            ├── HTTPS/JSON ──► [Node/TS 薄后端] ──► Gemini（默认）/ 智谱（备选）
[Android 壳]┘                      │
                                   ├── 元数据库（厂商待定）
                                   └── 展示图等文件存储（厂商待定）
客户端 ──直连──► OpenFreeMap + MapLibre
国内腾讯云 API ──经新加坡代理──► 国外 API（Gemini 等）
```

### A.2 客户端

| 项 | 结论 |
|----|------|
| 第一版目标 | **Web + Android**；iOS 后做，共用同一套后端 API |
| 形态 | **A：Web 为主 + Android 薄壳**（TWA/WebView 一类） |
| 为何 A | 第一版问题面更小（地图走已验证的 MapLibre GL JS）；不按个人技术栈选型 |
| 升级路径 | 若壳在选图/EXIF/地图上撞墙，再评估 RN/Flutter（B） |
| 地图 | 客户端直连 **OpenFreeMap + MapLibre**；后端不代理瓦片 |
| 防灰屏 | 常驻大概世界底图（见 `04f`）；实现细节后置 |

### A.3 后端

| 项 | 结论 |
|----|------|
| 角色 | 薄 API：登录、识图代理、观察/旅途 CRUD、展示图处理与存储接入 |
| 语言 | **TypeScript (Node)** |
| 将来本地 CV | 可另起 **Python** 工人，经 HTTP/队列与主 API 约定接口，不必重写主站 |
| 部署早期 | 用户 **腾讯云国内机**；具体 DB/对象存储产品 **待定**（看腾讯云方案再选） |

### A.4 账号与登录

| 项 | 结论 |
|----|------|
| 要登录 | **轻量登录**；默认识图额度、自备 Key、观察/旅途均挂账号 |
| 方式 | **邮箱魔法链接**（发信服务免费档；好友量级通常 $0） |
| 未登录 | 不消耗平台默认识图（至多极窄只读） |

### A.5 识图 Key

| 项 | 结论 |
|----|------|
| 平台默认 | 后端持有 Key；**默认 Provider = Gemini**；**备选 = 智谱** |
| 用户覆盖 | 设置里可存自己的 Provider + Key；此后该用户识图走自备 Key |
| 前端 | **永不打包平台默认 Key**；用户 Key HTTPS 入库，不完整回显 |
| 防冲爆 | **每账号每日默认识图次数上限**（N 以后定）；超限提示自备 Key 或次日；可加 IP/全局限流 |
| 出网 | 国内机经用户已有 **新加坡代理** 访问 Gemini 等；开发时补代理配置/小组件 |

### A.6 照片与存储

| 项 | 结论 |
|----|------|
| 库 | 只存**元数据** + 文件路径（或等价引用）；大图不进 SQL |
| 保留档位 | **仅识别** / **展示图** / **保留原图**（用户可选） |
| 默认 | **展示图**（识图可用更高清临时图；长期存压缩展示图） |
| 尺寸 | 具体像素/边长**以后定** |
| 厂商 | 对象存储/库 **腾讯云部署时再选** |
| 社交看他人图 | 非 MVP；不按此定早期规模（第 2 步 Out 社交 Feed） |

### A.7 核心数据对象（草案，块 B 可细化字段）

| 对象 | 含义 |
|------|------|
| User | 邮箱账号；可选自备识图凭证；日额度计数 |
| Trip | 用户自建旅途分组 |
| Observation | 一次观察：时空、分类结果、展示图引用、所属旅途、手改标记等 |

## 块 B：主路径交互（骨架够用，先搁置）

### B.1 主路径（已改主意，2026-08-05）

**动机：** 若选图后立刻把鉴定/时空等信息摊开编辑，没有「开包」感，差异化不如直接用 iNat。抽卡结算要当揭示高潮。

**流程（已定骨架）：**

1. **先进入某个自建旅途** → 相册选图并上传（可选填描述；选完即提交分析，中间不进 iNat 式确认编辑页）。  
2. 条目出现在**该旅途相册**里，状态为 **「分析中」**（可离开去做别的）。  
3. **分析完毕** → **弹框或整页**进入 **抽卡结算**。  
4. **结算页**再带上类 iNat 信息（鉴定、备注入口、日期时间、位置等）；揭示与收集感在前，明细在结算里/后。归属旅途在上传时已定。

此前「选图 → iNat 确认页 → 再识别/保存」方案 **作废**；iNat 截图改为 **结算页信息架构参考**，不是选图后的第一屏。

### B.2 「分析中」落点（已定）

- **B：先选旅途，条目进该旅途相册**（用户认为更酷；不做统一收件箱作主路径）。

### B.3 与参考界面的映射（结算阶段，草案）

| iNat 元素 | 出现时机（BioTrace） |
|-----------|----------------------|
| 媒体 | 旅途相册缩略图（分析中可见图）；结算页再展示 |
| 鉴定（俗名/学名等） | **结算揭示时**才完整亮出（可配合稀有度） |
| 备注 / 日期时间 / 位置 | 结算页可带；默认可来自 EXIF |
| 位置可见度 | **不做** |
| 添加至项目 | 上传前已选 **Trip**；结算不再重选（可后置「移旅途」） |
| 底栏大勾 | 语义改为结算确认/收下（细节待定） |

### B.4 分析完毕如何进结算（已定）

- **3：推送/轻提示 + 旅途相册可补开**  
  - 分析完可主动提示（弹层/整页，具体形态块 D 再抠）；  
  - 若当时忽略或错过，旅途相册条目变为「可开包/待结算」，点进同样进抽卡结算。

### B.5 识别「够格」界定（原则已定，细则后专项）

**共识：**

- **不能**用「是否到种」当理想线——种级高置信现实中很少。  
- **不能**把「界/门」级当成功（Seek「动物界 / Arthropods」= **未理想**）。  
- **不做死板「科一律弱 / 属一律够格」**，改为 **动态标准**：看该节点下的分化有多大、好不好辨。

**动态标准（已定方向）：**

- 后端维护一份**分类树/名录**（动物等；纯文本/结构化全量通常体量可接受，部署时下载入库，来源后定如 GBIF/COL 等）。  
- **小科 / 难辨分支**：下属属种很少、形态难拆时，停在**科**甚至个别**总科**也可算「凑合够格」。例：用户豆娘经历——iNat 到**细蟌总科**体感可接受（**举例，到时专项核实**，不现在当规则原文）。  
- **大科 / 差异极大分支**：科下五花八门，只到科 **不算精确** → 宜归弱结果或未理想，而不是正式够格。  
- 默认直觉仍对齐需求：**多数情况属 = 舒服成功线**；种 = 加成；动态规则是在科/总科等位置**放开或收紧**，不是取消属。

**抽卡侧三档（原则 OK）：**

| 档 | 含义（交互） |
|----|----------------|
| **结算** | 够格：正式抽卡揭示 |
| **弱结算** | 有方向但不够理想：可开弱卡/灰卡，明示阶元与局限 |
| **未理想识别** | 过粗或不可用：不开正式抽卡；相册失败/待补态，可重试 |

具体「某科算小还是大」→ 按树统计该节点下**属/种数量**等自动判定；**阈值专项调**（豆娘等个案届时核对）。白名单仅作日后补丁，不是 MVP 主路径。

技术侧产出建议：`finest_reliable_rank` + taxon id + 置信 + 分类链 → 服务端套动态规则 → 返回 `settle_tier: full | weak | none`。

### B.5.1 动态规则落地方式（已定）

- **2：按下属属/种数量自动算**小科/大科（及总科等节点是否够格）。  
- 阈值、用属数还是种数、总科如何计入 → 专项再定；本轮只锁算法方向。

### B.6 上传描述与地理信息（已定）

- 上传时可附带**描述**（可选），一并进分析 Prompt。  
- Prompt 硬约束：**以图片视觉证据为主**；描述仅辅助。禁止被文案带跑（例：图是野猪、文写「这就是一条蛇」→ 仍应按图判）。  
- **无 EXIF/GPS**：  
  - 描述里若写了地点 → 可作**参考先验**注入 Prompt，但置信/权重低于真实坐标，不作硬事实；  
  - 图无地址且描述也无地点 → **就没有地点**，照常分析与结算；**不弹提醒、不卡住上传**。  
- 不做「分析前强制地图补标」；缺位置不阻塞主路径。

### B.7 结算「收下」后（已定，低优先级可改）

- **1：回到该旅途相册**（刚收下的条目已揭开）。日后若要「去图鉴」入口可加，不挡主路径。

### B.8 待定 / 后置

- 三档各自：提示形态、相册态、稀有度怎么打折（并块 C）  
- 动态规则阈值与个案核实（专项）  
- 结算页内类 iNat 字段的编辑深度（块 D）

## 块 C：入侵警示与抽卡（骨架够用，先搁置）

承接需求 F1/F2、H4/H5：第一版都要可见可用；规则可先简单但须可解释。  
与块 B 衔接：抽卡在**结算揭示**；警示宜在结算/图鉴可见（具体位置本块定）。

### C.0 承接前提（已有）

- 警示：按**观察地点 + 公开/权威名录**；文案可用「当地关注/引入种」若「入侵」争议大。  
- 抽卡：N–UR 收集感；稀有度可解释（分布、类群罕见、旅途首次等），允许日后调。  
- 结算三档：结算 / 弱结算 / 未理想（弱档稀有度如何打折本块定）。

### C.1 讨论顺序（已定）

- 先 **抽卡 / 稀有度**，再入侵警示。

### C.2 抽卡稀有度（原则已定）

- **完全不做随机**（A）：同观察条件 → 档位稳定、可解释。  
- **珍惜/当地稀少 → 高稀有度**；常见 → 低。  
- **相对「当地」= 国家级**（已定）：按**观察点所在国家**的常见/稀有来定档，不做县/网格/半径（数据难搞、查询重）。  
- 同种可在 A 国高稀有、B 国低稀有；不在全球拍成同一档。  
- **预计算（已定）：** 离线/定期生成「taxon × 国家 → 常见度/稀有档」表，结算只查表；不做每次打外部 count。

**数据直觉（草案）：** 按「taxon × 国家」的出现量/相对常见度（公开源如 GBIF 等，具体源与阈值后定）映射档位。

### C.2.1 档位命名（已定）

- 对外先用 **N / R / SR / UR**（可日后改文案，骨架按四档）。  
- 阈值：国家常见度 → 四档的切分点，专项/实现时再定。

### C.2.2 无国家 / 弱结算（已定 · 2026-08-06 修订）

- **B：** 无国家（无 GPS 且描述也推不出国家）→ 按**全球常见度**给 N–UR；结算/详情**明示「位置不精确」**。  
- **弱结算不降稀有度**：稀有度只按 `finest_reliable_rank` 对应类群查表（例：可靠到科 → 查该科），与结算档（full/weak）脱钩。  
- 有国家时仍以「taxon × 国家」预计算表为准。

### C.2.3 不与「首次」挂钩（已定）

- **不做**旅途首次 / 个人图鉴首次抬档。  
- 稀有度只挂钩**动物（taxon）相对该国/全球的常见度**，不挂钩收集进度。

### C.3 抽卡骨架小结

主规则已齐：无随机、国家粒度预计算、N–UR、无国家走全球+位置不精确、弱结算不降稀有度（按可靠阶元查表）、不叠首次。  
后置：常见度数据源与切分阈值、全球表怎么建、结算动效（块 D）。

### C.4 入侵/关注种警示（讨论中）

#### C.4.1 露出时机（已定）

- **1：结算揭示时就打**（与开卡同一高潮，不藏到事后详情）。

#### C.4.2 文案（已定）

- 先 **B：偏中性**——对外用 **「当地引入/关注种」**（或同类说法），不先上「入侵种」硬词。  
- 对齐需求 H4；日后若名录带更强标签再考虑加档（不挡 MVP）。

#### C.4.3 匹配粒度（已定）

- **1：国家级**——按观察点所在国 × taxon 查「是否当地引入/关注」；与稀有度空间粒度一致。  
- 名录倾向公开国家清单（如 GRIIS 等经 GBIF 发布的 checklist）；具体源与预计算表形式实现时定。  
- 不做省/岛级匹配（后置）。

#### C.4.4 无国家 / 弱结算（已定）

- **无国家 → 不警示**：没有「当地」就无法匹配名录，**不编、不猜、不弱提示全球引入**。  
- **弱结算**：若已有国家且鉴定节点能对上名录 → **仍可警示**；对不上或过粗对不上 → 不警示。

### C.5 块 C 骨架小结

| 主题 | 要点 |
|------|------|
| 抽卡 | 无随机；taxon×国家预计算；N–UR；无国家→全球常见度+位置不精确；弱结算不降稀有度；不叠首次 |
| 警示 | 结算揭示打出；文案「当地引入/关注种」；国家级名录；无国家不警示 |

后置：名录/常见度具体数据源与阈值、结算动效文案（块 D）。

## 块 D：UI 信息架构（初步够用，已搁置）

> **性质说明（用户 2026-08-05）：** 本块所记均为**很初步的体验草案**，方便先按这个跑通手感；**不属于**此前 A–C / 需求里的核心硬约束，**后面肯定要改**。实现与评审时勿把 D 当不可动规格。  
> 定导航与关键屏职责，不定视觉高保真。  
> 已承接：主路径在**旅途相册**；结算/开卡/警示是高潮叠层；地图散点；个人图鉴回看。

### D.0 关键屏候选（草案，待收束）

| 屏 | 职责 |
|----|------|
| 旅途列表 | 自建旅途入口 |
| 旅途相册 | 分析中 / 待开包 / 已揭开；上传入口 |
| 抽卡结算 | 揭示 + N–UR + 引入警示 + 类 iNat 信息 |
| 世界/个人地图 | 观察散点浏览 |
| 图鉴/收集 | 按种类回看卡片 |
| 登录 / 设置 | 魔法链接；可选自备 Key 等 |

### D.1 主导航（已定）

- 底栏四项：**旅途 · 地图 · 图鉴 · 我的**  
- **默认打开：旅途列表**（主路径从旅途进相册上传）  
- **结算/开卡**为叠层或独立流程页，不占底栏  
- 登录、自备 Key、关于等进 **「我的」**

### D.2 图鉴 vs 旅途相册（已定）

- **A：**  
  - **旅途相册** = 某次旅行的照片时间线（分析中 / 待开包 / 已揭开；上传入口在此）。  
  - **图鉴** = 按**种类**的收集卡（N–UR 等），**跨旅途去重**；抽卡收集感落在这里。  
- 一条观察既进旅途相册，也（够格揭开后）更新图鉴条目。

### D.3 地图默认视野（初步）

- 先按 **1：全部观察散点**；视野尽量框住用户的点（点很少时可世界概览 + 常驻底图防灰屏）。  
- 可后置「按旅途筛选」；非核心。

### D.4 未登录（初步）

- **2：** 未登录可逛**空壳/演示向**界面（如地图底图、产品说明）；**上传、识图、图鉴与个人旅途数据要登录**（与块 A「登录后才用平台默认识图」一致）。

### D.5 块 D 小结（均为可改草案）

| 项 | 初步约定 |
|----|----------|
| 底栏 | 旅途 · 地图 · 图鉴 · 我的；默认旅途 |
| 旅途 vs 图鉴 | 旅行时间线 vs 跨旅途种类卡（去重） |
| 地图 | 默认全部观察散点 |
| 未登录 | 可逛壳/演示；写操作与个人数据需登录 |

后置：各屏线框、结算动效、空态文案——实现前再抠，不必当规格锁死。
